## 통째로 담지 않는 이유

**발표된 곡을 그대로 넣으면 한 바퀴마다 조용해집니다.** 앞뒤에 무음이 있고 끝이
페이드아웃이라, `music.ts` 가 `loop = true` 로 돌리면 그 자리가 「화면이 바뀌었다」보다 크게
들립니다. 앞의 셋이 실제로 그랬습니다 — 앞 0.2~0.3초, 뒤 0.3~2.9초.

그래서 곡의 가운데에서 **마디 수가 정수인 구간** 하나를 뗍니다. 그리고 그 구간 다음에 실제로
이어지던 소리를 구간의 머리에 반 마디 겹칩니다. 머리로 돌아온 자리에 진짜 이어지던 소리가
잦아들며 깔리므로, 돌아온 것이 아니라 이어진 것으로 들립니다.

재는 것은 [`web/tools/check-music.ts`](../../tools/check-music.ts) 입니다. **브라우저에서
풀어 봅니다** — `music.py` 는 굽기 직전의 파형을 보지만, 게임에서 소리를 내는 것은
`decodeAudioData` 이므로 그쪽에서 풀리는지는 그쪽에서 풀어 보아야 압니다.

```
npx tsx tools/check-music.ts
```

|재는 것|지금|
|--|--|
|앞뒤 무음|셋 다 0ms|
|한 바퀴 도는 자리의 표본 층|그 곡 자신의 표본 층 99.9퍼센타일의 0.04~0.07배. 묻힙니다|
|한 바퀴 도는 자리의 음량 층|1.1~3.7dB — 그 곡이 원래 오르내리는 폭(3.0~5.5dB) 안입니다|

## 크기 맞추기

**봉우리만 맞추면 화면마다 크기가 다릅니다.** 봉우리는 드럼 한 대가 정하고 사람이 듣는
크기는 그 아래의 평균이 정하므로, 봉우리를 같게 맞춘 셋이 3dB 씩 벌어집니다.

그래서 평균을 −15.5dBFS 로 맞추고, 그 위로 올라간 봉우리만 0.85 에서 무르게 눌렀습니다.
눌린 것은 표본의 0.6~1.7% 이고, 셋의 평균이 0.1dB 안에 들어옵니다. 효과음이 `audio.ts` 에서
맞춰지는 것과 같은 방식이고, 값은 효과음의 `TARGET_RMS` 보다 낮게 두어 배경이 자리를 비켜
줍니다.

**봉우리를 1.0 이 아니라 0.85 에 두는 이유가 있습니다.** vorbis 는 되풀 때 원래보다 살짝
넘겨 나오고, 브라우저에서 재면 0.6dB 위입니다 — 1.0 에 붙여 구우면 그만큼 깎입니다. 앞의 셋이
그렇게 1.04 로 깎여 있었습니다.

## 다시 만드는 법

```
python samples/clover/design-data/tools/music.py --fetch   # 받고 자릅니다
python samples/clover/design-data/tools/music.py --bake    # 받아 둔 것으로 다시 자릅니다
python samples/clover/design-data/tools/music.py           # 지금 놓인 것을 재어 봅니다
```

곡의 주소는 앨범 쪽에서 찾습니다. 파일 이름이 해시라 여기 적어 두어도 언젠가 어긋나므로,
도구가 그때그때 조회합니다.

받은 mp3 를 그대로 담지 않습니다. **320kbps 로 셋이 24MB 이고, 웹 빌드 전체가 16MB
입니다.** 한 바퀴만 vorbis 로 구우면 셋이 3.9MB 입니다.

## 이 곡을 고른 이유

**신스웨이브입니다.** 이 게임에서 사람의 역할은 패를 보고 고르는 것이라, 몰아치는 곡은 그
판단을 방해합니다 — 카드가 놓이고 칩이 꽂히는 소리가 위에서 들려야 하므로 배경은 자리를
비켜 주어야 합니다. 셋은 밝기로 갈랐습니다.

|화면|무엇을 보고 골랐는가|
|--|--|
|타이틀|저역이 두툼하고 고역이 낮은 야경. 도입이 0초라 곧바로 붙습니다|
|판|기복이 가장 작습니다(2.9dB). 효과음이 그 위에 올라섭니다|
|상점|고역이 가장 밝습니다. 넘어간 것이 곧바로 들립니다|

기본 음량은 효과음과 같은 눈금이지만 파일이 더 낮게 구워져 있어서 배경이 아래에 깔립니다.
옵션에서 효과음과 **따로** 끄고 줄일 수 있습니다.
