# UI 전면 개편 실행 기준

> [디자인 언어](language.md) · [연출 설계](../presentation.md) · [화면의 문법](../ui.md)

---

이 문서는 새 디자인 언어를 만드는 제안서가 아닙니다. `language.md` 와 기존 연출 스펙을
정본으로 두고, 실제 화면을 그 수준까지 옮기는 작업 순서와 합격 조건을 기록합니다.

## 바뀌지 않는 것

- 플레이 보드의 배경은 셰이더 프랙탈입니다. 정적인 테이블 그림으로 대체하지 않습니다.
- 이 게임은 카지노 게임이 아닙니다. 칩 더미·주사위·룰렛·펠트 테이블·금장 장식 같은 도박
  소품을 분위기 장식으로 쓰지 않습니다.
- `핸드`·`버리기`·`금액`·`안티` 앞에 아이콘을 붙이지 않습니다. 작은 글과 큰 값의 위계로
  읽게 합니다.
- 빈 조커·소모품 트레이는 슬롯 묶음이 아니라 **테두리 없는 반투명 면 하나**입니다.
- 정렬 이름은 `무늬순`입니다.
- 그림이 필요한 자리를 선·막대·도형으로 대신하지 않습니다. 타이틀 카드, 장면 삽화,
  물건 얼굴은 완성된 래스터 원화를 사용합니다.

## 도형을 허용하는 범위

런타임 `Graphics` 는 동적으로 값이 달라지는 마스크, 히트 영역, 진행량, 셰이더 입력,
파티클과 순간 연출에만 씁니다. 판·단추·칸·트레이·장면 삽화처럼 모양이 고정된 화면 부품은
원화 기반 스프라이트 또는 9분할 스프라이트입니다. 원화 누락을 장식 도형으로 감추지 않습니다.

## 작업 단계

### 1. 공통 외피와 첫 인상

- [x] 판·값 칸·단추 네 계단을 원화 기반 9분할 스프라이트로 교체
- [x] 타이틀의 시작·콜렉션·리더보드 임시 선화를 전용 삽화로 교체
- [x] 왼쪽 HUD 외피와 블라인드 정보 판을 전용 스프라이트로 분리
- [x] 빈 조커·소모품 트레이를 테두리 없는 반투명 면으로 정리
- [ ] 런 시작·챌린지·콜렉션 등 전면 화면의 빈 그림 자리를 실제 콘텐츠 그림으로 교체

### 2. 플레이 조작 위계

- [ ] `낸다`를 한 화면의 유일한 금색 주동작으로 유지하고 `버린다`는 위험 동작으로 분리
- [ ] 비활성·호버·누름이 0.16초 상태 전환 안에서 재질과 깊이로 구분되는지 전 겉면 확인
- [ ] 손패 선택, 정렬, 취소, 키보드·패드 포커스가 같은 시각 언어를 쓰는지 확인
- [ ] 1280×800 기준과 축소 화면에서 글·버튼·카드가 겹치지 않는지 확인

### 3. 점수와 조커 연출

- [ ] 카드 → 칩/배수 → 총점의 인과가 한 번의 시선 이동으로 읽히는지 타임라인별 캡처
- [ ] 보통 조커 발동은 고정 음성·가로 흔들림으로 제한하고 불필요한 파티클은 넣지 않음
- [ ] 판 변경은 뒷면을 거치는 플립, 복사는 지속 링크, 비활성은 시듦으로 서로 다르게 표현
- [ ] 같은 조커의 연속 발동은 세기를 누적하되 정보 판독을 가리는 화면 플래시는 제한
- [ ] 환희 연출은 프랙탈을 교체하지 않고 그 위에 겹쳤다가 원래 배경으로 돌아오게 유지

### 4. 상점·정산·보조 화면

- [ ] 상점 상품·가격·구매 가능 상태가 장식보다 먼저 읽히는지 확인
- [ ] 정산은 원인별 줄 → 합계 → 수령 순서가 현재 스펙의 박자를 지키는지 확인
- [ ] 옵션·컬렉션·리더보드의 표와 목록을 공통 판/단추 스프라이트로 통일
- [ ] 빈 상태·잠금 상태에 임시 막대나 가짜 썸네일이 남지 않게 함

### 5. 합격 게이트

- `npm run check`, `npm test`, 트레이·누름·크롭·언어 검사를 통과해야 합니다.
- `tools/shoot-look.ts` 의 전 화면 캡처를 기본·검정·남색·밝은 회색 겉면에서 비교합니다.
- 12·24·36·48·72 이외의 글자 크기와 36·48·60·72 이외의 버튼 높이를 새로 만들지 않습니다.
- 캡처 검토에서 프랙탈 훼손, 카지노 장식, 임시 도형 삽화, 트레이 테두리, 금지된 앞 아이콘이
  하나라도 보이면 완료로 보지 않습니다.
