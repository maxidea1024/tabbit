## P2 — 데이터 저작 (끝)

격자 40개를 채우고, 워크북 9개로 렌더링하고, 변환을 통과시켰습니다.

```
python samples/clover/design-data/tools/seed.py                    # 격자를 처음 만들 때만
dotnet run --project samples/clover/design-data/tools/Authoring    # 격자 → 워크북
dotnet run --project src/Tabbit.csproj -- --recipe samples/clover/design-data/recipe.jsonc
python samples/clover/design-data/tools/verify.py
```

|무엇|수|
|--|--|
|격자|**40개**|
|데이터 행|1,300 남짓|
|조커|**150종** · 효과 행 **178**|
|효과 행 전체|**400 남짓** (조커 · 소모품 · 보스 · 바우처 · 태그 · 덱 · 강화 · 인장)|
|`Custom`|**1건** — `pruning_shears` 하나|
|`verify.py`|**통과 24 · 실패 0**|

**효과의 99% 이상이 데이터에 있습니다.** 그것이 이 단계의 답입니다 — 두 구현이 갈라질 수
있는 자리가 하나뿐입니다.

도구 쪽에서 3건이 나왔고 [도구 보고](tool-findings.md)에 있습니다. 하나는 결함이고
(**변종의 멤버가 배열이면 C# 생성이 예외**) 둘은 설계된 제약입니다. 셋 다 우회하였고,
우회가 남아 있는지는 `verify.py` 가 봅니다.

남은 것 하나는 조커 그림입니다 — `Assets.OnMissing` 이 지금 `warn` 이고 경고가 150건입니다.
P4 에서 그림이 들어오면 `error` 로 바꿉니다.

## P3 — 코어 (TypeScript) (끝)

화면을 모르는 규칙 엔진과 헤드리스 러너입니다. **코어의 표면은 함수 하나입니다** —
`apply(data, state, action)` 이 상태와 이벤트 배열을 돌려줍니다.

```
cd samples/clover/web
npm install
npm run check                          # 타입 검사
npm test                               # 테스트 56개
npm run headless -- --seed CLOVER-0001 --random 600
```

|무엇|어디|
|--|--|
|결정론 원시|`core/units.ts` · `core/rng.ts` · `core/hash.ts`|
|족보 판정|`core/hand.ts`|
|효과 VM|`core/vm/` — 조건 41종 · 연산 36종|
|득점 파이프라인|`core/scoring.ts`. **규격의 줄 순서가 곧 이 파일의 줄 순서입니다**|
|런의 흐름|`core/run.ts` · `core/shop.ts`|
|헤드리스|`headless.ts` — 리플레이 재생과 무작위 완주|

### 판정

|기준|결과|
|--|--|
|타입 검사|**통과.** 우리 코드는 `strict` 입니다|
|테스트|**56개 통과** — 족보 12종 · 판정 규칙 5종 · 연산 15종 · 결정론 13종|
|완주|시드 8개에서 **예외 없이** 종료 상태까지 돕니다|
|리플레이|**13개**를 구웠고, 다시 돌리면 같은 해시를 냅니다|
|`Custom`|득점 경로에서 도는 것은 **`pruning_shears` 하나**뿐입니다|

### 안테 8에 대하여

계획에는 「헤드리스로 안테 8까지 완주」라고 적었습니다. **그것은 코어의 판정 기준이
아니었습니다** — 지금 헤드리스의 수를 두는 부분은 「낼 수 있는 조합 중 점수가 가장 높은
것」을 고르는 정도이고, 그 실력으로 도달하는 곳이 안테 4~5입니다.

|시드|결과|
|--|--|
|`CLOVER-0001` · `0003` · `0007` · `0008`|안테 4|
|`CLOVER-0005`|안테 5|
|`CLOVER-0002`|안테 1|
|`CLOVER-0004` · `0006`|안테 2|

**코어가 못 가는 것이 아니라 두는 쪽이 못 가는 것입니다.** 그래서 판정을 「예외 없이 종료
상태까지 돈다」로 바꾸고, 도달 안테는 러너가 좋아질수록 올라가는 수로 기록해 둡니다.

### 규격에 더한 것 하나

**재발동 중에는 재발동을 받지 않습니다.** `Red Seal` 이 그 카드를 한 번 더 발동하는데, 그 한
번에서 인장이 또 요청하면 자기 자신을 끝없이 부릅니다. 깊이 상한(`Const_Score` 의
`MaxRetriggerDepth`)은 그 위의 안전장치이지 규칙이 아닙니다.

**테스트를 쓰다가 나왔습니다** — 「인장 하나가 칩 2를 더한다」가 16이 아니라 30이 나왔고,
그 자리에서 규격이 비어 있던 것이 드러났습니다.

### 도구 쪽에서 나온 것 셋

[도구 보고](tool-findings.md)의 §4 · §5 · §6 입니다. **생성 코드를 실제로 읽고 돌려 보아야
나오는 것들이고, 변환은 셋 다 성공으로 끝납니다.**

|무엇|무게|
|--|--|
|다형 변종의 옵셔널 멤버에서 「비었음」이 사라집니다|규약으로 덮었습니다|
|`typescript` 산출물이 `strict` 에서 컴파일되지 않습니다|**결함.** 옵셔널 `foreign` 의 타입이 사실과 다릅니다|
|`readAllBytes` 가 ESM 에서 돌지 않습니다|**결함.** `"type": "module"` 프로젝트에서 파일 읽기가 전부 막힙니다|

## P4 — 웹 게임 (PixiJS) (끝)

코어가 내는 이벤트를 받아 그리는 층입니다. **규칙은 여기 없습니다** — 어디에 놓을지와 얼마나
세게 보일지뿐이고, 뒤쪽의 수치는 `Const_Feel` 이므로 데이터입니다.

```
cd samples/clover/web
npm run dev                # 브라우저에서 열립니다
npm run build              # 정적 산출물
npx tsx tools/shoot.ts     # 화면을 굽습니다
```

|--|--|

|에디션 셰이더 4종|`shader/editions.ts`. 파라미터가 `EditionVisual` 테이블입니다|
|연출|`render/juice.ts`. 이벤트를 박자로 만드는 것과 재생하는 것이 갈려 있습니다|
|소리|`render/audio.ts`. **음원 파일이 없습니다** — 파형을 만듭니다|

### 판정

|기준|결과|

### 눈으로 본 것이 잡은 것 셋

**타입 검사와 테스트가 통과해도 화면은 틀릴 수 있습니다.** 그림을 굽고 사람이 본 뒤에 고친
것이 셋입니다.

|무엇|어떻게 드러났는가|
|--|--|
|득점이 어디서 일어나는지 보이지 않았습니다|낸 카드가 곧바로 사라져서 숫자가 화면 가운데에 떴습니다. **낸 카드를 연출이 끝날 때까지 붙잡습니다**|
|족보 이름이 `ThreeOfAKind` 로 나왔습니다|식별자를 그대로 그렸습니다. 표시 이름을 `StringTable` 에 넣고 거기서 읽습니다|
|상점에 손패와 칩·배수가 남았습니다|**코어의 결함입니다** — 라운드가 끝날 때 패를 비우지 않았습니다|

셋째는 화면의 문제가 아니라 코어의 문제였고, 그림이 없었으면 P6 대조에서야 드러났을
것입니다.

### 그림에 대하여

**조커 150종의 일러스트가 아직 없습니다.** 지금은 식별자에서 만든 문양으로 그립니다 — 같은
조커는 언제나 같은 모양이고 희귀도가 테두리 색입니다. `Assets.OnMissing` 이 `warn` 이고
경고가 150건입니다.

그림이 들어오면 `error` 로 바꾸고 문양을 스프라이트로 갈아 끼웁니다. **그때부터 그 검사가
자리표가 아니라 게임이 띄우는 파일을 봅니다.**

## P4 뒤에 고친 것

**손으로 해 보고 나서 드러난 것들입니다.** 타입 검사도 테스트도 그림도 통과한 상태에서
사람이 해 보고 나온 것이므로, 이것들이 왜 자동 검사에 걸리지 않았는지도 같이 적습니다.

|무엇|왜 그랬는가|검사가 왜 못 봤는가|
|--|--|--|
|화면 오른쪽과 아래에 빈 곳이 남았습니다|화면 크기를 `renderer.width` 로 쟀습니다. 그것은 픽셀 밀도가 곱해진 물리 크기라서 밀도 2인 화면에서 배율이 두 배로 계산됩니다|스크린샷 도구가 기준 해상도·밀도 1로만 찍었습니다. **배율이 늘 1이면 배율 계산이 틀려도 그림이 맞습니다**|
|카드 아래쪽에 마우스를 올리면 카드가 떨었습니다|마우스가 올라오면 카드가 위로 들리고, 들린 카드가 마우스 밑에서 빠져나가 곧바로 내려옵니다. 내려오면 다시 들립니다|Pixi 의 `pointerover`·`pointerout` 이 정상으로 오간 것이므로 오류가 없습니다|
|무엇을 하는 게임인지 알 수 없었습니다|규칙을 적어 둔 곳이 문서뿐이었습니다|화면에 없는 것은 그림 검사의 대상이 아닙니다|
|조커를 한 번도 못 봤습니다|조커는 상점에서만 오고, 상점은 블라인드를 하나 격파해야 열립니다. 그 사실이 화면에 적혀 있지 않았습니다|자동으로 두는 러너는 규칙을 알고 있으므로 막히지 않습니다|

고친 것은 넷입니다.

|무엇|어디|
|--|--|
|논리 크기로 재기|`main.ts`. 스크린샷 도구도 1600 × 1000 · 밀도 2로 올려 같은 조건을 만듭니다|
|**쉬는 자리로 호버 판정**|`render/game.ts` 의 `updateHover`. 이벤트를 쓰지 않고 마우스 자리와 카드가 쉬는 네모를 견줍니다. 조커도 같은 문제가 있었으므로 같이 고쳤습니다|
|게임 방법 판|`ui/guide.ts`. 첫 판에서 한 번 저절로 열리고, 그 뒤로는 버튼입니다|
|지시문 한 줄|`render/game.ts` 의 `hintText`. 국면마다 다음에 누를 것을 적습니다|

## 부스터 팩

**표에만 있고 규칙도 화면도 없던 것입니다.** `BoosterPack` 15종이 상점 상태에 채워지기는
하였지만 살 수 없었습니다.

팩은 사는 것이 아니라 뜯는 것이므로 상태가 하나 더 필요합니다.

|무엇|어디|
|--|--|
|뜯어 놓은 팩|`state.pack`. 펼쳐진 것과 앞으로 몇 장 더 고를 수 있는가|
|액션 3개|`buy_pack` · `pick_pack` · `skip_pack`|
|무엇이 들어 있는가|`core/shop.ts` 의 `rollPackCard`. 갈래가 어느 표에서 뽑을지를 정합니다|
|화면|`render/game.ts` 의 `drawPackRow` 와 `syncPack`|

규칙 셋을 규격으로 둡니다.

- **다 고르거나 건너뛰기 전에는 상점을 나가지 못합니다.** 나가는 액션이 무효가 됩니다.
- **자리가 없으면 고르지 못합니다.** 팩은 그대로 열려 있으므로 다른 것을 고르거나 건너뜁니다.
- **뜯어 놓은 팩이 해시에 들어갑니다.** 두 구현이 여기서 갈라진 것을 그 자리에서 알 수
  있어야 합니다. 필드는 `canonical` 의 끝에 붙였습니다.

`Standard` 팩 카드의 강화·인장·에디션 확률은 원작에서 수집하지 못한 값이므로 `Const_Economy`
에 세 줄로 두었습니다 — 수치가 확인되면 그 세 줄만 고칩니다.

## 연출을 다시 짠 것

**「돌아간다」와 「할 만하다」는 다릅니다.** 손으로 해 보고 나온 지적을 하나씩 고친 기록입니다.

### 색

초록 단색이던 것을 남색 바탕에 강조색 셋으로 바꿨습니다. **채도가 높은 것은 셋뿐입니다** —
칩은 파랑, 배수는 빨강, 돈은 금색. 나머지는 회청색 계열이므로 이 셋이 눈에 들어옵니다.

블라인드마다 배경과 딱지의 색이 다릅니다. 스몰은 파랑, 빅은 보라, 보스는 붉고, 상점은 청록,
끝났으면 색이 빠집니다 — **이름을 읽지 않아도 어디까지 왔는지가 보입니다.**

### 한 방을 만드는 것들

|무엇|어디|왜|
|--|--|--|
|**히트스톱**|`game.ts` 의 `stop`|때린 순간 연출의 시계가 멈춥니다. 용수철과 파티클은 계속 움직이므로 화면이 얼어붙어 보이지 않습니다|
|**배경 펄스**|`shader/background.ts` 의 `uPulse`|무늬가 통째로 밝아지고 고리가 가운데에서 바깥으로 퍼집니다|
|**패널 번쩍임**|`game.ts` 의 `flashPanel`|왼쪽의 숫자가 바뀌는 자리에 파티클을 뿌리면 숫자를 가립니다. 패널 자체가 빛납니다|
|**화면 번쩍임**|`flashScreen`|큰 것에만 씁니다 — 배수 곱하기, 점수 합치기, 격파, 런의 끝|
|**색수차**|`shader/punch.ts`|화면 흔들림만 있으면 「움직였다」로 읽히고, 색이 어긋나면 「맞았다」로 읽힙니다|
|**음이 올라가는 소리**|`showBeat` 의 `chain`|득점 사건마다 반음이 올라갑니다. 사람이 「쌓인다」로 읽는 것이 이것입니다|
|**커지는 세기**|`chain` 을 5로 나눈 값|뒤로 갈수록 튀는 크기와 흔들림이 커집니다. 마지막 한 방이 앞의 것보다 확실히 큽니다|

### 고른 카드

셰이더 하나가 두 가지를 합니다 — 고른 카드는 밝아지고 사선 광택이 흐르고 테두리에 빛이 돌고,
**고르지 않은 카드는 색이 빠지고 어두워집니다.** 고른 것만 밝히면 몇 장을 골랐는지가 세어야
알 수 있고, 나머지가 물러나면 한눈에 읽힙니다.

버튼 줄 오른쪽에 칸 다섯이 있습니다. 「최대 5장」 이라고 적어 두는 것보다 칸이 채워지는 것이
빠릅니다.

### 동전

돈이 오갈 때 동전이 날아갑니다. 벌면 번 자리에서 금액 칸으로 날아가 하나씩 꽂히고 **꽂히는
소리의 음이 하나씩 올라갑니다.** 잃으면 금액 칸에서 튀어나가 떨어집니다.

라운드가 끝날 때의 돈은 갈래마다 따로 알립니다 — 격파 보상 · 이자 · 남은 핸드 · 남은 버리기.
**코어가 `MoneyChanged` 를 내지 않아 연출이 볼 것이 없던 것을 고쳤습니다.**

### 국면 화면의 시점

**국면이 바뀌었어도 앞 국면의 연출이 돌고 있으면 화면을 갈지 않습니다.** 낸 카드가 아직 판에
있는데 상점이 그 위에 그려지던 것과, 마지막 카드의 결과를 보기도 전에 끝난 판이 덮이던 것이
같은 결함이었습니다.

`presented` 하나가 그 조건입니다 — 연출이 끝났고, 낸 카드가 치워졌고, 동전이 다 꽂혔는가.
상점·버튼·딱지·배경 색이 전부 이것을 봅니다.

끝난 판은 럼블과 함께 뜹니다. 크기가 0.45에서 1.16을 지나 1로 돌아오고 그동안 판이 떨립니다.
문구도 「패배」·「승리」로 바꾸고, **왜 끝났는지를 적습니다** — 「안테 3 · 빅 블라인드에서
216점이 모자랐습니다」.

### 눈으로 본 것이 잡은 것

|무엇|어떻게 드러났는가|
|--|--|
|조커 두 장이 무지개 잡티로 덮여 이름을 읽을 수 없었습니다|홀로그래픽 셰이더가 노이즈를 무지개의 **위상**에 더했습니다. 픽셀마다 색이 달라지므로 카드가 잡티가 됩니다. 노이즈는 밝기에만 얹고, 섞는 양은 데이터가 어떤 값이어도 절반을 넘지 않게 묶었습니다|
|폴리크롬의 `strength` 가 1을 넘어 밝은 자리가 통째로 무지개가 되었습니다|셰이더에서 묶습니다. 데이터가 범위를 벗어나도 화면이 무너지지 않아야 합니다|
|낸 카드가 게이지에 붙어 있었습니다|머리글과 게이지를 위로, 낸 카드를 아래로 옮겼습니다|
|「+$1」 같은 글씨가 흰 카드 위에 겹쳐 읽히지 않았습니다|낸 카드 아래로 내렸습니다|

## 스테이크 조회 (고침)

**표에 8종이 있고 코어가 그것을 읽고 있었는데, 찾는 식이 어긋나 흰색을 뺀 7종이 걸리지
않았습니다.**

`Stake` 의 열쇠는 `StakeKind` enum 이고 `name` 칸은 표시 이름입니다. 그런데 찾는 식이
이렇게 적혀 있었습니다.

```ts
entry.name === state.stake || String(entry.stake) === state.stake
```

리플레이와 `newRun` 이 넘기는 값은 enum 의 이름(`White`)입니다. 왼쪽은 `흰색` 이고 오른쪽은
`'1'` 이므로 **어느 쪽도 맞지 않아 줄을 찾지 못하고 기본값이 쓰였습니다.** 이렇게 적힌 곳이
넷이고, 맞게 적힌 곳은 `core/metrics.ts` 하나였습니다 — 그쪽만 enum 의 이름을 함께
보았습니다.

|검사가 왜 못 봤는가|
|--|
|게임이 늘 흰색으로 시작했습니다. `newRun(..., 'red_deck', 'White', ...)` 이 두 곳에 고정되어 있었고 **덱과 스테이크를 고르는 화면이 없었습니다** — 아래의 [고르는 화면](#덱과-스테이크-고르는-화면)에서 고쳤습니다|
|**흰색은 기본값과 값이 같습니다.** 안테 1열이고 버리기 증감이 0이며, 스몰 블라인드 보상 $3 은 `Blind` 표에 적힌 값과 같습니다|
|구워 둔 리플레이 13개가 전부 흰색이었습니다. 스테이크를 바꾼 리플레이가 하나도 없었습니다|

고친 것과 더한 것입니다.

|무엇|어디|
|--|--|
|찾는 자리를 하나로|`core/stake.ts` 의 `stakeRow`. 셋 다 받습니다 — enum 이름 · 숫자 문자열 · 표시 이름|
|부르는 쪽 넷|`core/run.ts` 의 `applyStake` · `targetOf` · `rewardOf`, 그리고 `core/metrics.ts` 의 `stakeIndexOf`|
|런 정보 패널|`render/game.ts`. 지금 스테이크에 띠가 그려지지 않았고 이름이 현지화되지 않았습니다 — `stake.<슬러그>.name` 을 읽습니다|
|리플레이 8개|`stake-white` 에서 `stake-gold` 까지. 한 시드(`CLOVER-0009`)에 스테이크만 바꿉니다|

흰색 리플레이 13개의 해시는 한 개도 움직이지 않았습니다. **바뀌지 않는 것이 판정입니다** —
흰색의 값이 기본값과 같으므로 고친 것이 흰색 런에 닿을 경로가 없습니다.

**그리고 같아야 할 것만 같습니다.** `stake-black` 은 `stake-green` 과, `stake-orange` ·
`stake-gold` 는 `stake-purple` 과 해시가 같습니다 — 그 셋의 차이는 스티커뿐이고 스티커가
아직 없습니다.

### 스티커 3종 (고침)

`Stake` 의 `sticker` · `sticker_percent` 를 읽는 곳이 없었습니다. **붙이는 자리는 이미 하나로
모여 있었으므로** — `core/vm/operations.ts` 의 `stickerFor` 이고 상점 · 팩 · 태그 ·
`CreateCard` · 챌린지의 시작 소지품이 전부 거칩니다 — 그 안에 추첨을 더했습니다.

|한 일|
|--|
|`RngStreamKind` 에 `Sticker` 를 더했습니다. 데이터와 생성 코드가 함께 바뀌므로 워크북부터 다시 만들었습니다|
|`stickerFor` 가 스테이크의 확률을 굴립니다. **자격을 보기 전에 굴립니다** — 조커 하나에 한 번씩 굴려야 그 뒤의 추첨이 어느 조커가 나왔는지에 흔들리지 않습니다|
|스테이크 리플레이 8개를 `CLOVER-0007` 로 다시 굽었습니다|

**리플레이 21개의 해시가 전부 움직였습니다.** 상태 해시에 스트림마다의 상태가 들어가므로
(`core/hash.ts`) 스트림 하나를 더하면 흰색 런의 해시도 달라집니다. **달라지지 않아야 하는
것은 액션과 지표이고, 21개 가운데 `stake-gold` 하나만 달라졌습니다** — `Rental` 이 값을 $1로
만들고 라운드마다 $3을 가져가므로 그 런의 상점 선택이 갈립니다. 지문은 `2b6a4d16` 에서
`c5a1f0e2` 로 바뀌었습니다.

시드를 `CLOVER-0009` 에서 `CLOVER-0007` 로 옮긴 것은 게이트가 효과를 지나치기 때문입니다.
`CLOVER-0009` 의 주황색 런은 안테 2에서 끝나 `Perishable` 이 5라운드에 닿지 않았고, 그러면
스티커가 붙은 것만 확인되고 무력화는 확인되지 않습니다. `CLOVER-0007` 은 여덟이 모두 안테
4까지 갑니다.

|스테이크|붙은 스티커|
|--|--|
|흰색 · 붉은색 · 초록색|없음|
|검은색 · 파란색 · 보라색|`Eternal` 1개|
|주황색|`Perishable` 1개 — 5라운드에 닿아 무력화되었습니다|
|황금색|`Rental` 1개|

### 남은 것

원작과 다른 것 둘을 [덱과 스테이크](parity/decks-and-stakes.md#원작과-다른-것-둘)에 적었습니다.
조커 하나에 스티커 하나이고, 누적되지 않습니다. `Perishable` 이 붙지 않는 조커의 목록은
수집되지 않았으므로 `Perishable` 과 `Rental` 은 어느 조커에나 붙습니다.

## 덱과 스테이크 고르는 화면

**데이터와 코어와 리플레이가 다 있고 화면만 없었습니다.** 판을 시작하는 두 자리가
`newRun(..., 'red_deck', 'White', ...)` 로 고정되어 있어서, 게임에서는 15덱 가운데 붉은 덱
하나와 8종 가운데 흰색 하나만 돌았습니다.

|더한 것|어디|
|--|--|
|고르는 판|`ui/setup.ts`. 덱 15칸 · 스테이크 8칸 · 오른쪽에 시작 조건|
|타이틀의 단추|`ui/title.ts`. **시작의 왼쪽**이고 고른 것이 단추에 적힙니다|
|저장|`clover.options` 의 `deck` 과 `stake`. 표에 없는 값은 `validSetup` 이 붉은 덱으로 되돌립니다|
|확인 도구|`tools/check-setup.ts`|

**칸마다 그 덱의 뒷면을 그립니다.** 덱이 정하는 것 중 한 판 내내 보이는 것이 뒷면이므로,
이름만 적힌 목록에서는 무엇을 고르는지가 판을 시작한 뒤에야 보입니다. `render/card-back.ts`
의 그리는 함수를 그대로 부르므로 여기서 맞으면 판에서도 맞습니다.

**잠긴 칸이 없습니다.** 결제가 없는 로그라이트에서 해금은 순수한 지연이므로 15덱과 8종을
처음부터 전부 엽니다. `Deck.unlock` 은 표시용 문자열로 남아 있고 이 화면은 읽지 않습니다 —
필요해지면 컬럼 하나와 잠긴 표시 하나입니다.

### 화면으로 갈리지 않는 것

`tools/check-setup.ts` 를 따로 둔 이유입니다. **덱은 뒷면과 시작 조건으로만, 스테이크는
요구 점수와 보상으로만 나타나므로, 엉뚱한 덱으로 시작해도 그림은 그럴듯합니다.** 그래서
화면이 `deck` 과 `stake` 를 알리게 두고(`publishPeek`) 그 둘을 봅니다.

|보는 것|값|
|--|--|
|저장을 비운 처음|`red_deck` · `White`|
|검은 덱과 파란 스테이크를 눌렀을 때|`clover.options` 에 `black_deck` · `Blue`|
|시작한 판|`deck` 이 `black_deck`, `stake` 가 `Blue`|
|검은 덱의 핸드 -1|블라인드를 고른 뒤 핸드가 3 (기본 4)|
|파란 스테이크의 버리기 -1|버리기가 2 (기본 3)|

마지막 둘은 **블라인드를 하나 고른 뒤에 봅니다.** 판이 서기만 한 자리에서는 핸드와 버리기가
0이고, 0으로는 시작 조건이 걸렸는지 갈리지 않습니다.

## 리더보드의 번역 65줄

**`tools/check-lang.ts` 가 한동안 실패하고 있었습니다.** 리더보드와 계정 화면을 만들 때
`StringTable` 에 한국어와 영어만 채웠고, 일본어 · 중국어 간체 · 중국어 번체 · 독일어 넷이
비어 있었습니다 — `ui.lb.*` 59줄과 `ui.button.*` 7줄, 그리고 뜻이 비어 있는 줄 셋입니다.

빠진 번역은 화면에서 **열쇠가 그대로 보입니다**(`ui.lb.title`). 그 규약이 있어 게임은 그대로
돌았고, 그래서 눈으로 보지 않으면 드러나지 않았습니다.

65줄을 채웠습니다. 낱말은 이미 있는 줄에서 가져왔습니다 — 덱은 `デッキ` · `牌组` · `牌組` ·
`Deck`, 스테이크는 `ステーク` · `赌注` · `賭注` · `Einsatz`, 핸드는 `ハンド` · `出牌` ·
`出牌` · `Hände` 입니다.

### 채우고 나서 드러난 것 둘

**말이 길어지면 칸을 넘칩니다.** 한국어에 맞춰 둔 칸이 독일어와 일본어에서 터졌고, 넘친 글은
잘리지 않고 옆의 것 위에 그려집니다.

|무엇|고친 것|
|--|--|
|타이틀의 덱 단추|`Plasma-Deck · Violetter Einsatz` 가 200픽셀 칸의 양쪽으로 삐져나왔습니다. `ui/widgets.ts` 의 `Button` 이 **글이 칸을 넘치면 글자를 줄입니다** — 어느 말이 가장 긴지는 데이터가 정하고 덱 15종 × 스테이크 8종이므로 칸을 넓히는 것으로는 끝나지 않습니다|
|스테이크 칸의 이름|한국어는 색 하나(`흰색`)이지만 다른 말에는 「스테이크」가 붙습니다(`ホワイトステーク`). 두 줄까지 접고 **글자 단위로 끊습니다** — 일본어와 중국어에는 공백이 없어 낱말 단위로만 접으면 한 줄로 남습니다|

넷 중 가장 긴 조합(`Verlassenes Deck · Schwarzer Einsatz`)과 일본어 · 중국어 간체 ·
한국어를 눌러 보고 확인했습니다.

## 카드 한 벌의 축

> 규격은 [카드 한 벌](card-set.md)에 있습니다. 여기는 만들면서 드러난 것들입니다.

**덱과 다른 축을 하나 더 두었습니다.** 덱은 런의 시작 조건이고 이것은 그 52장이 어떻게
보이는가입니다 — 판이 도는 중에 갈아입어도 규칙은 하나도 달라지지 않으므로 리플레이와
해시에는 들어가지 않고 옵션에만 남습니다.

|격자|무엇|
|--|--|
|`CardSet`|한 벌 하나. `art_dir` 이 비면 무늬와 랭크를 그립니다|
|`CardSetSuit`|무늬마다의 색. **네 색을 다 적습니다** — 빠진 것을 코드의 기본값으로 채우면 그 기본값이 어느 세트의 색인지가 코드에만 있게 됩니다|

`Feel` 워크북에 두었습니다. 겉모습이므로 `Const_Feel` 과 `EditionVisual` 과 같은 자리입니다.

### 세 벌 (그림 0컷)

|세트|얼굴|무늬의 색|
|--|--|--|
|`classic` 정본|`art/card/` 의 그림 52장|그림 안에 있습니다|
|`line` 선화|`pips.ts` 가 그립니다|검정 · 빨강|
|`four_color` 4색|`pips.ts` 가 그립니다|스페이드 검정 · 하트 빨강 · 클럽 초록 · 다이아 파랑|

**그림을 한 장도 더하지 않고 셋이 나옵니다.** 4색은 온라인 포커의 규격이고 색약 대응이라는
쓸모가 있어, 시스템을 그림 없이 검증하면서 화면에 넣을 명분이 함께 섭니다.

### 색을 고르던 자리 넷

`red ? COLOR.red : COLOR.black` 이 네 곳에 적혀 있었습니다 — 손패 · 덱 보기의 작은 카드 ·
덱 보기의 무늬 표식 · 팩과 상점의 미리보기입니다. 넷을 `render/card-set.ts` 의 `suitInk`
하나로 모았습니다. 뒷면을 한 곳에 둔 것과 같은 이유이고, **그 넷 중 하나만 놓쳐도 그 자리의
카드가 다른 벌이 됩니다.**

덱 보기의 무늬 표식은 한 자리 다릅니다. 어두운 판 위이므로 세트가 검정으로 정한 무늬는
그대로 그리면 보이지 않고, 그 하나만 밝은 잉크색으로 그립니다.

### 갈래를 대신하는 그림 폴더

`artFor` 가 받던 것이 갈래(`card` · `joker` · `tarot` …)였고, 트럼프만 갈래 하나로는
모자랍니다 — 세트마다 한 벌이므로 `CardSet.art_dir` 이 정하는 이름이 그대로 폴더가 됩니다.
확장자 판정은 `card` 로 시작하는지만 봅니다. 세트의 폴더를 `card/cats` 처럼 아래에 두면
같은 판정에 걸립니다.

### 뒷면 — 무늬는 세트, 색은 덱

처음에는 컬럼을 두지 않았습니다. 앞면만 바꾸는 세 벌뿐이어서 쓰는 세트가 없었고, **쓰는
것이 없는 컬럼은 읽는 코드가 있어도 검사가 지나갑니다.** 그림 있는 세트가 들어오면서
`CardSet.back` 을 더하였고, 무늬가 그 결과 맞는 여섯에 적었습니다 — `bone_court` 가 `Arcane`,
`dragons` 가 `Zodiac`, `tin_kings` 가 `Checker`, `forest_kin` 과 `blooms` 가 `Brush`,
`bugs` 가 `Worn` 입니다.

**색 두 개는 늘 덱의 것입니다.** 덱이 정하는 것 중 한 판 내내 보이는 것이 뒷면이므로,
세트가 그것을 통째로 가져가면 어느 덱으로 하고 있는지가 화면에서 사라집니다 — 「붉은 덱 +
뼈의 궁정」은 붉은 룬 뒷면입니다.

### 고르는 자리 — 글자 단추의 되돌림

처음에는 옵션 판의 카드 탭에 **이름 단추 셋**을 두었습니다. 「정본 · 선화 · 4색」이 글자로만
적혀 있었고, 그것이 틀렸습니다 — **고르는 것이 「그 카드가 어떻게 보이는가」이므로 글자로는
고를 수 없습니다.** 고르고 판을 열어 본 뒤에야 무엇을 골랐는지 알게 됩니다.

`Row.cards` 를 두어 칸마다 **그 벌의 카드 넉 장**을 그립니다. K♠ · 7♥ · 4♣ · A♦ 이고, 그
벌의 색으로 그립니다 — 지금 고른 벌의 색으로 그리면 셋이 같아 보여 글자 단추와 다를 것이
없습니다. 그림이 있는 벌은 그림을 그대로 세웁니다.

고른 그 자리에서 갈아입습니다. 겉모습이므로 도는 판의 규칙에 닿지 않습니다.

|드러난 것|고친 것|
|--|--|
|출처가 설명 줄에서 접혀 단추 위에 그려졌습니다|`Row.foot` 을 두어 **고른 것들 아래에** 적습니다. 설명 줄은 한 줄짜리 자리입니다|
|`CC0` 의 `0` 이 수의 색으로 칠해졌습니다|시트의 글을 「공유 재산」으로 고쳤습니다. 정본 52장의 라이선스를 부르는 이름이 그것이고, 서식 규칙을 문자열 하나 때문에 고치지 않습니다|

`tools/check-cards.ts` 가 세 벌로 판을 하나씩 돌립니다. **세트는 규칙에 닿지 않으므로
갈아입었는데 화면이 그대로여도 어긋나는 값이 하나도 없습니다** — 그래서 손패와 덱 보기를
찍어 눈으로 봅니다.

### 그린 얼굴의 다시 그리기

**세트로 내놓을 수 있는 얼굴이 아니었습니다.** `pips.ts` 의 그린 얼굴은 「그림이 없을 때」의
대체로 만든 것이고, 거기에 이름만 붙여 세트 둘로 내놓았던 것이 잘못입니다.

|무엇이 잘못이었는가|
|--|
|**그림 카드가 빈 액자로 읽혔습니다.** 88 × 124 에서 문양이 27픽셀이면 액자가 문양보다 크고, 옅게 칠한 판은 검정 무늬에서 회색이 되어 카드가 아니라 자리표로 보입니다|
|**`10` 의 모서리 글자가 얼굴의 무늬와 겹쳤습니다.** 두 글자인 랭크가 하나뿐이라 그 하나에서만 겹치고, 열 장이 전부 그렇습니다|
|무늬가 커서 8·9·10 이 빽빽했습니다|

고친 것입니다. 눈으로 보며 세 번 되돌렸습니다 — 판을 넓히고 문양을 키운 것이 첫 번째,
판을 아예 걷어낸 것이 두 번째, 가운데 띠와 얼굴의 작은 무늬를 걷어낸 것이 세 번째입니다.

|무엇|어떻게|
|--|--|
|그림 카드|**액자도 띠도 없습니다.** 큰 문양 둘이 위아래로 마주 봅니다 — 에이스가 큰 무늬 하나로 읽히는 것과 같습니다. 문양은 38픽셀이고, 아래쪽은 판을 뒤집어 그려 실제로 마주 봅니다|
|문양 셋|칼 · 잔 · 왕관입니다(`blade` · `chalice` · `crown`). 셋이 한 벌의 이야기가 되어야 J·Q·K 의 순서가 그림으로도 읽힙니다|
|무늬 배치|안쪽 상자를 `0.30~0.70` 에서 `0.33~0.67` 로 좁히고 위아래를 `0.17` 에서 `0.235` 로 내렸으며, 무늬를 `0.155` 에서 `0.128` 로 줄였습니다|
|`10` 의 모서리|**두 글자인 랭크가 그 하나입니다.** 한 글자에 맞춘 19픽셀로 두 글자를 적으면 얼굴의 무늬와 겹치고, 겹치는 것은 열 장 전부입니다 — 무늬 상자를 그만큼 좁히면 나머지 마흔두 장이 좁아지므로 좁히는 것은 글자 쪽입니다(`cornerSize`)|

`faces.html` 을 두었습니다. **게임 안에서는 한 번에 넉 장쯤만 보이므로** 랭크 13종이 한 결로
보이는지는 판에서 확인이 되지 않습니다 — 52장을 손패 크기로 세우고, 그림 카드와 에이스를
2.1배로 함께 세웁니다.

## 그림이 있는 세트 14벌

**세트 하나가 52컷이 아니라 12컷입니다.** 그림이 카드를 덮고 **모서리의 랭크와 무늬는
화면이 그 위에 그립니다** — 그래서 그림이 필요한 것은 그림 카드 J·Q·K 뿐이고, 무늬가
넷이므로 12컷입니다. 숫자 카드는 그린 무늬가 그대로이고 세트의 색을 씁니다.

|갈래|세트|
|--|--|
|귀여운 것|`cats` 고양이 · `dogs` 강아지 · `otters` 수달 · `squirrels` 다람쥐 · `geckos` 게코|
|숲과 꽃|`forest_kin` 숲의 아이들 · `bugs` 곤충 · `blooms` 꽃|
|판타지|`dragons` 용 · `bone_court` 뼈의 궁정 · `tin_kings` 양철 왕|
|스포츠|`baseball` 야구 · `basketball` 농구 · `soccer` 축구|

**무늬마다 다른 개체입니다.** 넷이 같은 그림이면 세트 하나에 그림이 셋뿐이므로, 무늬가
털색·유니폼색·비늘색을 정합니다 — 스페이드는 검정 쪽, 하트는 붉은 쪽, 클럽은 초록 쪽,
다이아는 크림과 금 쪽입니다.

스포츠는 소지품이 다릅니다. **J·Q·K 의 서열은 그대로 읽혀야 하므로** 도구를 든 것이 J,
잔을 든 것이 Q, 왕관을 쓴 것이 K 이고, 그 도구가 배트와 공이며 잔이 우승컵입니다.

랭크마다의 소지품은 `pips.ts` 의 문양 셋과 같은 이야기입니다 — J는 칼을 들고 Q는 잔을 들며
K는 왕관을 씁니다. 그린 얼굴과 그림 얼굴이 같은 것을 가리켜야 한 게임의 카드가 됩니다.

|한 일|어디|
|--|--|
|`CardSet.art_has_index`|그림에 모서리가 들어 있는가. **정본 한 벌만 참입니다** — 밖에서 온 52장이라 모서리까지 그려져 있습니다|
|`CardSet.paper`|종이의 색. 그림의 바탕과 같아야 그림 없는 랭크가 한 벌로 보입니다 — 굽힌 그림의 크림을 재어 세트마다 적었습니다|
|프롬프트|`art.py` 의 `CARD_SET_STYLE` · `SET_SUIT_TRAIT` · `SET_RANK_PROP`. 세트를 더하는 것이 화풍 한 줄과 무늬 넷과 랭크 셋입니다|
|그림|14벌 × 12컷 = 168컷 · 6분 · 약 $2.9. `webp` 이고 모서리만 투명합니다|

**컬럼을 끼워 넣었다가 변환이 거절했습니다.** `art_has_index` 와 `paper` 를 `credit` 앞에
두었더니 태그가 밀렸고, 도구가 「이미 배포된 리더가 살아남지 못한다」고 알렸습니다 — 뒤에
붙여 태그를 지켰습니다.

### 그림이 카드가 되기까지 되돌린 것 셋

**굽는 것보다 얹는 것이 오래 걸렸습니다.** 셋 다 눈으로 보고서야 드러났습니다.

|무엇|왜|고친 것|
|--|--|--|
|**네모난 종이 조각**|그림이 카드를 덮으므로 종이의 둥근 모서리가 가려집니다|굽는 단계에서 모서리를 투명하게 자릅니다. 반지름은 폭에 대한 비율(`0.102`)이므로 손패에서도 덱 보기에서도 같은 모양입니다|
|**바탕의 크림이 강화로 읽힘**|**이 게임에서 카드 바탕에 색이 들면 강화입니다** — 따뜻한 크림은 `Gold` 와 같은 신호입니다|테두리 안쪽 고리에서 바탕색을 재고 그 색에서 가까운 것을 전부 바꿉니다. 세트의 `paper` 도 종이색으로 되돌렸습니다|
|**바꿔 놓고도 누렜음**|**화면이 그림에 종이색을 곱합니다** — 강화를 색으로 알리기 때문입니다. 바탕이 크림이면 크림 × 크림이 되어 한 번 더 누렇게 뜹니다|바탕을 **흰색**으로 바꿉니다. 그 곱이 정확히 종이색이 됩니다 — **정본 52장의 얼굴이 흰색인 것이 그 이유였습니다**|
|**테두리가 두 겹**|테두리를 그림에 구웠더니 자른 자리와 그린 자리 사이에 바탕색 한 겹이 남았습니다|**테두리는 화면이 그림 위에 그립니다.** 그림에서는 걷어냈습니다 — 구운 선은 디버프의 회색으로 바뀌지도 않습니다|

마지막 것이 요점입니다. **그림이 가진 것과 화면이 그리는 것의 경계**가 그림 카드 12컷에서
정해졌습니다 — 그림은 그림과 모서리의 투명뿐이고, 종이·테두리·모서리의 랭크와 무늬는 전부
화면입니다.

## 옵션 판 — 스크롤과 폭

카드 탭을 만들면서 세 가지가 드러났습니다. **셋 다 「어떻게든 밀어넣으려 한 것」입니다.**

|드러난 것|고친 것|
|--|--|
|세트가 여섯이 되니 한 줄에 여섯 칸이 되었습니다|`CARD_COLUMNS` 3으로 접습니다. 좁아진 칸의 카드는 무엇을 고르는지 보이지 않고, 고르는 것이 겉모습이므로 그것이 보이지 않으면 그 줄의 뜻이 없어집니다|
|판이 내용만큼 자라 화면을 넘길 수 있었습니다|**본문이 굴러갑니다.** 판을 `MAX_HEIGHT` 에서 멈추고 창 밖으로 나간 줄은 자릅니다. 넘치는 만큼만 오른쪽에 손잡이가 섭니다|
|그림의 출처가 줄 하나를 늘 차지했습니다|**쪽지로 옮겼습니다.** 칸에 올리면 뜹니다 — 정본 하나에만 있는 글입니다|

판의 폭을 520에서 720으로 넓혔습니다. 여섯 말을 세 칸씩, 카드 여섯 벌을 세 칸씩 세우는
폭입니다.

**판의 자리를 화면이 알립니다.** `ModalStack.box` 를 `publishPeek` 이 실어 보내므로, 판을
누르는 도구가 그 자리를 다시 세지 않습니다 — 판이 자란 날에 엉뚱한 곳을 누르고 아무 말도
하지 않던 것이 실제로 이 판에서 한 번 일어났습니다.

## `Graphics` 에 붙던 자식

`drawCardBack` 이 넘겨받은 `Graphics` 에 마스크와 무늬를 자식으로 붙이고 있었고, Pixi 가
그것을 예고 폐기로 알렸습니다. **덱 고르는 판이 부팅에서 15번 부르자 콘솔이 그 경고로
덮였습니다** — 판이 도는 동안에는 덱 더미 다섯 장뿐이어서 묻혀 있었습니다.

부모를 `Container` 로 바꾸고 그리는 것은 자기 `Graphics` 를 만들어 담습니다. 부르는 곳
다섯이 함께 바뀌었고, 카드 한 장은 뒷면이 담기는 통을 따로 가집니다 — 종이는 그린 선이고
뒷면은 통 하나이기 때문입니다.

### 색 있는 바탕의 예외

168컷 가운데 한 장(`baseball/club_jack`)이 **주황 판**으로 나왔습니다. 프롬프트에 크림
바탕을 적어 두었지만 생성기가 한 번 어긴 것입니다.

색 거리로 지웠더니 **누끼가 뜯겼습니다.** 그 주황에서 가까운 색이 인물 안에도 있어서
방망이와 살색에 구멍이 났고, 인물과 바탕 사이의 완충 픽셀은 남아 테두리가 지저분해졌습니다.

그래서 판정을 하나 두었습니다 — **크림인 것만 지웁니다.** 색이 도는 판은 손대지 않고
`--ground` 가 그 장을 세며, 그 장은 다시 굽습니다. 문턱은 실측입니다: 따뜻한 크림이 48이고
생성기가 그린 주황 판이 122이므로 그 사이(65)입니다.

## 빠져 있던 문구 7개

조커의 설명에 열쇠가 그대로 적혀 있었습니다 — 「라운드 종료 시 «scope.RandomInDeck»를
무늬로 바꿉니다」. `describe()` 는 없는 문구에 «표시» 를 달아 눈에 띄게 하는데, **눈에 띄는
것은 그 조커를 실제로 만난 사람뿐입니다** — 조커 500종 가운데 하나를 만나기까지 판을 몇 번
돌아야 하는지가 그 게이트의 성능이었습니다.

|빠진 것|
|--|
|`phrase.scope.RandomInDeck` · `RandomConsumable` · `JokerRight` · `JokerLeftmost`|
|`phrase.blind.Small` · `Big` · `Boss`|

일곱을 채우고 **게이트를 두었습니다**(`test/phrase.test.ts`). 셋을 봅니다.

|보는 것|왜|
|--|--|
|갈래마다의 enum 이름이 실재하는가|`describe` 의 `PHRASE_FAMILIES` 가 가리키는 enum 이 데이터에 있어야 합니다|
|enum 값마다 문구가 있는가|열쇠를 세는 것이고, 쓰이지 않는 값까지 봅니다|
|**설명에 «표시» 가 남지 않는가**|효과 10갈래의 모든 행을 실제로 문장으로 만들어 봅니다. 열쇠를 세는 것만으로는 조건과 연산의 변종이 빠진 것을 볼 수 없습니다|

## 포일 셰이더의 좌표

**대각선 띠가 흐르지 않고 제자리에서 떨렸습니다.** 수식은 사인파이므로 끊길 수 없고, 끊긴
것은 좌표였습니다.

`vTextureCoord` 는 필터가 받은 텍스처 위의 자리입니다. 그 값은 `uOutputFrame.zw *
uInputSize.zw` 이고, 앞쪽은 조커가 화면에서 차지한 사각형(장치 픽셀 단위로 올림)이며 뒤쪽은
Pixi 가 내준 텍스처의 크기(**2의 거듭제곱**)입니다. 조커는 매 프레임 흔들리므로 그 나눗셈이
프레임마다 달라집니다.

|양|값|
|--|--|
|의도한 흐름|프레임당 0.005 rad|
|사각형 1픽셀이 주는 위상 변화|프레임당 **0.09 rad**|
|2의 거듭제곱 경계를 넘을 때|한 번에 **6 rad**|

무늬의 좌표를 `vShapeCoord` 로 옮겼습니다. 필터가 도는 사각형 위의 0..1 이므로 그 나눗셈이
없습니다. 홀로그래픽의 잡티도 같은 좌표로 옮겼습니다 — 그것도 조커가 흔들릴 때마다 자리를
옮기고 있었습니다.

|함께 고친 것|왜|
|--|--|
|`uTilt` 의 계수를 2.0에서 0.6으로|마우스가 조커 줄을 지나가면 위상이 4 rad — 주기의 0.64 — 움직였습니다|
|`flow_speed` 를 3000에서 12000으로|띠가 카드를 한 번 지나는 데 40초였습니다. 「루핑이 안 된다」의 절반이 이것입니다|
|홀로그래픽 · 폴리크롬 · 네거티브의 속도|네거티브의 맥박은 주기가 78초였습니다|

**셰이더 소스는 템플릿 문자열 안입니다.** 주석에 백틱을 하나 쓰자 문자열이 끊기고, 끊긴
자리부터 GLSL 이 아니라 자바스크립트로 읽혔습니다 — 두 프레임을 견주는 확인 도구가 그것을
검출했습니다.

**남은 것 하나.** 사각형은 회전한 카드를 감싼 것이므로 회전이 흔들리는 만큼 무늬도 조금씩
늘어납니다. 완전히 없애려면 카드 로컬 좌표로 되돌리는 행렬을 유니폼으로 넘겨야 하고, 그것은
`uShape` 가 회전 중에 몇 픽셀 어긋나는 것과 같은 자리입니다.
