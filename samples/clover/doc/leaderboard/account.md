**계정은 리더보드에 오르기 위한 것이고 게임에 필요하지 않습니다.** 로그아웃 상태의 게임은
지금과 한 줄도 다르지 않습니다 — 세이브도 옵션도 `localStorage` 그대로입니다.

|제공자|어디에|왜|
|--|--|--|

**GitHub 은 두 곳에서 각각 차단합니다.** 한쪽이 잘못 배포되어도 다른 쪽이 남습니다.

|어디|어떻게|
|--|--|
|서버|켤 제공자를 `AUTH_PROVIDERS` 환경변수로 받고, **`NODE_ENV=production` 에서 `github` 이 있으면 부팅하지 않습니다.** 환경변수 하나로 새는 것이므로 확인이 부팅에 있어야 합니다|
|클라이언트|로그인 판의 GitHub 단추가 `import.meta.env.DEV` 안에만 있습니다. **`vite build` 의 산출물에는 그 단추의 코드 자체가 없습니다** — 조건이 아니라 빌드가 지우는 것입니다. 서버가 목록에 `github` 을 보내더라도 배포 빌드는 그리지 않습니다|

`import.meta.env.DEV` 는 이미 [game.ts](../../web/src/render/game.ts) 의 개발용 단추가 쓰는 자리입니다 — 같은 규약입니다.

**셋 다 OAuth 2.0 authorization code 입니다.** Apple 만 `id_token` 을 함께 주고 이름을 처음
한 번만 주므로, 첫 로그인에서 표시 이름을 받는 것은 어느 제공자에서나 같게 우리 판에서
합니다.

## 저장 구조

```
account ──< identity      (provider, subject)
   │
   └── profile            (handle, tier, created_at)
   │
   └──< session           (refresh token 의 해시, 만료)
```

|표|무엇|들고 있지 않는 것|
|--|--|--|
|`account`|계정 하나. 식별자와 만든 시각|—|
|`identity`|`(provider, subject)` → 계정. **한 계정에 여럿**|이메일 · 이름 · 사진. **제공자가 주지만 받지 않습니다**|
|`profile`|`handle` · 등급 · 지난 시즌 등급|—|
|`session`|refresh token 의 해시와 만료|token 원문|

**계정과 신원을 나눈 것은 나중에 둘째 제공자를 붙이기 위해서입니다.** Google 로 만든 계정에
Discord 를 붙이면 `identity` 한 줄이 늘어나고 기록은 그대로입니다. 지금은 붙이는 화면이
없고 표만 그렇게 둡니다.

## 표시 이름 `handle`

|규칙|값|
|--|--|
|길이|3~16|
|글자|영문 · 숫자 · `_`. **대소문자를 구분하지 않고 유일합니다**|
|바꾸기|30일에 한 번|
|처음|첫 로그인 직후 우리 판에서 받습니다. **제공자의 이름을 가져다 채우지 않습니다**|

**유니코드를 받지 않는 것은 순위표의 폭 때문입니다.** 이름 칸의 폭이 정해져 있고 6개 언어의
글자 폭이 다릅니다. 영문과 숫자면 16자가 어느 언어에서나 한 줄입니다. 나중에 여는 것은
칸을 넓히면 되는 일이고, 닫는 것은 이미 만든 이름을 빼앗는 일이므로 좁게 시작합니다.

**금칙어는 두지 않습니다.** 신고 단추 하나와 서버의 `handle` 초기화가 그 자리입니다 — 목록은
목록에 없는 것을 막지 못하고 이름을 6개 언어로 심사할 사람이 없습니다.

## 세션

**한 계정이 여러 기계에서 동시에 로그인합니다.** `session` 표에 기계마다 한 줄이고, 한 줄을
지우는 것이 그 기계의 로그아웃입니다 — 다른 기계는 그대로입니다. 데스크탑에서 놀다가 폰에서
순위를 보는 것이 막힐 이유가 없습니다.

|무엇|어떻게|
|--|--|
|access token|JWT · 15분 · 서명만 확인. 서버가 상태를 갖지 않습니다|
|refresh token|무작위 32바이트 · 30일 · `session` 표에 해시로. **한 번 쓰면 새 것으로 바뀝니다**|
|기계 수|**한 계정에 10개까지.** 넘으면 가장 오래 쓰지 않은 것이 밀려납니다 — 지금 쓰고 있는 기계가 밀려나지 않는 방향입니다|
|바꾼 직후|**60초 동안은 바로 앞의 것도 받습니다.** 서버가 바꾼 응답을 받지 못한 기계가 예전 token 으로 한 번 더 오는 일이 있고, 그때 로그아웃시키면 사람이 이유를 알 수 없습니다|
|기계 목록|`GET /me` 의 `devices`. 이름 · 만든 때 · 마지막으로 쓴 때|
|한꺼번에 로그아웃|`POST /auth/logout {"everywhere": true}`. 열쇠가 샜을 때의 길입니다|
|클라이언트 보관|`localStorage` 의 `clover.session`. 옵션과 같은 자리이고 같은 방어입니다 — 저장소가 막혀 있으면 이번 판만 로그인입니다|
|로그아웃|**그 기계의 `session` 행 하나만** 삭제합니다. access token 은 15분 안에 만료됩니다|

**랭크 시드는 계정의 것이지 기계의 것이 아닙니다.** 데스크탑에서 받은 시드로 폰에서 놀아도
됩니다 — 다만 **시드 하나에 제출 하나**이므로 두 기계가 같은 시드로 끝내면 먼저 도착한 것만
올라갑니다.

**쿠키가 아닌 이유는 데스크탑과 안드로이드입니다.** 같은 웹 빌드가 `file://` 과 Capacitor
안에서도 도는데 거기에서 쿠키는 각각 다르게 동작합니다. 토큰을 우리가 들고 헤더로 보내면
셋에서 같습니다.

## 로그인의 흐름

```
[제목 화면 · 리더보드 단추]
        │ 로그아웃 상태
        ▼
[로그인 판]  ── 제공자 단추 ──▶  GET /auth/{provider}?return=<지금 주소>
                                       │  제공자로 redirect
                                       ▼
                               제공자의 동의 화면
                                       │
                                       ▼
                               GET /auth/{provider}/callback
                                       │  identity 조회 · 없으면 account 생성
                                       │  refresh token 발급
                                       ▼
                               <return>#session=<한 번 쓰는 code>
                                       │
                                       ▼
[게임이 다시 뜹니다]  POST /auth/exchange { code } ──▶ access + refresh
        │
        ▼ profile.handle 이 비어 있으면
[이름 판] ──▶ POST /me/handle
        │
        ▼
[리더보드 판]
```

**게임이 다시 뜨는 것을 피하지 않습니다.** 팝업으로 로그인하면 안드로이드에서 팝업이 막히고
데스크탑에서 팝업이 다른 창입니다. redirect 는 셋에서 같고, 게임의 부팅은 2초 안입니다.
다만 **런 도중에 로그인하지 않습니다** — 단추가 제목 화면에만 있으므로 잃을 것이 없습니다.

`#session=` 뒤의 것이 token 이 아니라 한 번 쓰는 code 인 것은 주소가 기록에 남기 때문입니다.
code 는 60초 안에 한 번 바꿀 수 있고 그다음은 없습니다.

## 플랫폼

|플랫폼|되돌아오는 길|상태|
|--|--|--|
|웹|`https://<게임 주소>/#session=…`|**이 문서의 범위**|
|데스크탑 (Electron)|`clover://auth#session=…` 커스텀 스킴. 시스템 브라우저에서 로그인|보류. 포장이 되어 있으므로 스킴 등록만 남습니다|
|안드로이드 (Capacitor)|같은 커스텀 스킴 · `App.addListener('appUrlOpen')`|보류|

**보류인 둘은 서버가 아니라 되돌아오는 길만 다릅니다.** 서버의 `return` 이 허용 목록에
있으면 어느 스킴이든 같은 code 를 붙여 보냅니다.

## 삭제

`DELETE /me` 가 계정과 신원과 세션과 **모든 제출을** 지웁니다. 순위표에서 그 자리가 빠지고
아래가 한 칸씩 올라옵니다. 되돌리지 않습니다.
