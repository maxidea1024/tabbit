# 리더보드

> [clover 문서 목록으로](readme.md)

---

게임은 혼자 하는 것입니다. **로그인은 선택이고, 로그인하면 리더보드가 열립니다.** 리더보드가
첫 번째이고 다른 것은 나중입니다 — 계정이 생기면 저장 동기화와 도전과제도 그 위에 올릴 수
있지만, 이 문서는 리더보드로 한정합니다.

이 문서가 설계의 정본입니다. **설계만 있고 구현이 없습니다.**

|무엇|어디|
|--|--|
|지표 · 분할 · 보드 격자 · 티어와 등급 · 시즌|[보드](leaderboard/boards.md)|
|소셜 로그인 · 계정 · 표시 이름 · 세션|[계정](leaderboard/account.md)|
|랭크 시드 · 제출 · 서버 재현 · 판정 · 버전 지문|[제출과 검증](leaderboard/submission.md)|
|Express · Redis · PostgreSQL · API · docker-compose|[서버](leaderboard/server.md)|
|들어가는 자리 · 판 · 런 끝의 연출|[화면](leaderboard/screens.md)|

## 결정 7개

|결정|이유|
|--|--|
|**보기도 오르기도 로그인이 필요합니다**|로그인 전에는 판 자체가 없습니다. 제목 화면의 단추가 로그인 창을 엽니다|
|**서버가 다시 돕니다.** 점수는 받지 않고 리플레이를 받습니다|코어가 결정론적이고 헤드리스 러너가 이미 있습니다. 클라이언트의 숫자를 믿을 이유가 없습니다|
|**랭크 런은 서버가 준 시드로만 시작합니다**|시드를 고르게 두면 좋은 시드를 찾아 오는 것이 실력이 됩니다. 시드는 한 번 쓰고 없어집니다|
|**보드는 시트의 행입니다**|어느 지표를 어느 축으로 나누는가가 데이터입니다. 보드 하나를 더하는 데 코드가 바뀌지 않습니다|
|**시즌은 데이터 버전에 묶입니다**|밸런스가 바뀌면 점수가 비교되지 않습니다. 시즌 하나 안에서는 규칙 지문이 하나입니다|
|**티어는 둘입니다** — 스테이크와 등급|스테이크는 보드를 나누는 축이고, 등급은 시즌 순위에서 나오는 표시입니다|
|**챌린지 런은 챌린지 보드에만 오릅니다**|시작 조건이 다른 것을 같은 표에 두지 않습니다. 원작이 챌린지에서 해금을 올리지 않는 것과 같은 이유입니다|

## 이미 있는 것

**리더보드가 필요로 하는 것의 절반이 이미 있습니다.** 대조 게이트를 위해 만든 것들입니다.

|리더보드가 필요로 하는 것|이미 있는 것|
|--|--|
|같은 입력에 같은 결과|`newRun` · `apply` — 코어가 화면과 시간을 모릅니다|
|리플레이 형식|`Replay` — 시드 · 덱 · 스테이크 · 액션 배열. 13개가 구워져 있습니다|
|서버에서 도는 코어|`headless.ts` 가 Node 에서 같은 코어를 돕니다|
|상태의 지문|`snapshotHash()`|
|코어가 바뀐 것을 아는 방법|`bake-replays.ts --check` — 구워 둔 해시가 어긋나면 보고합니다|
|런의 설정|`seed` · `deckId` · `stake` · `pools` — 해시에 들어가지 않는 넷|
|6개 언어|`StringTable`|
|챌린지가 런의 설정이라는 것|[챌린지](challenge.md#코어-배선)의 `RunState.challengeId` — `pools` 와 같은 갈래이고 해시에 들어가지 않습니다. **리더보드가 더할 것이 없습니다**|

## 새로 만드는 것

|무엇|어디|
|--|--|
|**격자 2개**|`Leaderboard` 64행 · `Tier` 6행 — [보드](leaderboard/boards.md). `Meta.xlsx` 와 `schemas/meta.tbs` 가 그 자리입니다|
|**지표 계산**|`core/metrics.ts` — 스텝 배열에서 지표를 냅니다. 클라이언트와 서버가 같은 함수를 씁니다|
|**규칙 지문**|`public/data/version.json` — 빌드가 구워 둔 리플레이의 해시로 만듭니다|
|**서버**|`samples/clover/server/` — Express · Redis · PostgreSQL. 코어를 임포트합니다|
|**계정 클라이언트**|`web/src/net/` — 세션 · 제출 · 보드 조회. **코어를 건드리지 않습니다**|
|**판 3개 · 내 카드 · 런 끝의 한 줄**|리더보드 판 · 프로필 판 · 로그인 판 · 제목 화면에 상시로 보이는 내 순위 · 끝난 판의 순위 — [화면](leaderboard/screens.md)|

## 단계

|단계|무엇|판정|
|--|--|--|
|L0|`metrics.ts` 와 `version.json`. 헤드리스 러너가 지표를 함께 냅니다|구워 둔 리플레이 13개의 지표가 골든에 적힙니다|
|L1|서버 — 계정 · 세션 · 랭크 시드 · 제출 · 재현. docker-compose 로 뜹니다|리플레이 13개를 API 로 넣어 전부 `accepted`. 액션 하나를 바꾼 것은 `rejected`|
|L2|보드 — Redis 순위와 조회 API. 등급 산정|1만 계정을 합성해 넣고 어느 쪽 순위도 100ms 안에|
|L3|클라이언트 — 로그인 판 · 리더보드 판 · 프로필 판 · 내 카드 · 런 끝의 순위|playwright 로 눈 확인. 로그아웃 상태에서 게임이 전과 같습니다|
|L4|Google · Discord · Apple 실제 연결. GitHub 은 개발 환경에만|`vite build` 산출물에 `github` 문자열이 없고, `NODE_ENV=production` 서버가 `AUTH_PROVIDERS=github` 으로 뜨지 않습니다|

**L0 과 L1 은 화면이 없습니다.** 헤드리스와 API 만으로 판정이 끝나고, 화면은 그 위에
얹습니다.

### 챌린지와의 순서

**L0 이 [C4](challenge.md#단계) 뒤입니다.** `version.json` 의 지문이 구워 둔 리플레이의
해시인데, 챌린지의 C1 과 C4 가 그 해시를 움직입니다. 앞서 만들면 챌린지가 들어오는 날
전부 다시 만듭니다.

|챌린지의 단계|리더보드에서|
|--|--|
|C1 · C4 — 골든이 움직임|**L0 을 그 뒤에.** 지문을 한 번만 만듭니다|
|C5 — 코어 배선 (`challengeId`)|**L1 이 이것을 씁니다.** 서버의 `newRun` 인자가 그것입니다|
|C4 — 격자 4개|**챌린지 보드 21개의 행이 그때 만들어집니다.** `Leaderboard` 의 `challenge` 가 `Challenge` 를 가리키므로 먼저 있어야 합니다|
|C6 — 화면|`Challenge` 탭과 선택 화면의 기록 줄이 그 위에 붙습니다|

**챌린지 없이도 L0~L3 이 전부 됩니다.** 그때는 `Challenge` 탭이 없고 보드가 41개입니다 —
빈 탭을 그리지 않는 것이 [화면](leaderboard/screens.md#리더보드-판)의 규약입니다.

## 하지 않는 것

|무엇|왜|
|--|--|
|점수를 그대로 받는 것|재현이 가능한데 믿을 이유가 없습니다|
|자기 시드의 런을 올리는 것|시드 고르기가 점수가 됩니다. 자기 시드는 그대로 놀 수 있고 다만 오르지 않습니다|
|클라이언트에서 부정을 판정하는 것|클라이언트는 상대의 것입니다. 판정은 서버에만 있습니다|
|챌린지 진도를 서버에 두는 것|깬 챌린지의 목록은 [챌린지](challenge.md#진행-저장)의 세이브에 있습니다. 리더보드는 순위만 봅니다 — 저장 동기화는 계정이 생긴 다음의 일이고 이 문서의 범위가 아닙니다|
|유니티 · 데스크탑 · 안드로이드|웹이 먼저입니다. 데스크탑과 안드로이드는 같은 웹 빌드이므로 로그인의 되돌아오는 길만 다릅니다 — [계정](leaderboard/account.md#플랫폼)|
|이메일 저장|표시 이름과 제공자의 식별자만 있으면 됩니다. 들고 있지 않은 것은 새지 않습니다|
