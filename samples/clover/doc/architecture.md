# 런타임의 구조

> [clover 문서 목록으로](readme.md)

---

시트 한 벌에서 나온 데이터로 **온전한 게임 하나**를 만듭니다. 규칙과 수치가 전부 시트에 있고
코드는 그것을 해석합니다 — 그 사실을 리플레이로 확인하고, 그 확인이 이 샘플의 판정 기준입니다.

## 층 3개

```
   데이터 (테이블 46개)
          │
        코어
    (TypeScript)
          │
    연출 (PixiJS)
```

|층|무엇|규칙|
|--|--|--|
|데이터|생성된 읽기 코드와 `.tcb`|**시트에서 나옵니다.** 손으로 고치는 자리가 아닙니다|
|코어|규칙 엔진. 상태와 이벤트|**화면을 참조하지 않습니다.** 입력은 액션, 출력은 상태와 이벤트 배열|
|연출|화면 · 소리 · 입력|코어를 호출하고 이벤트를 받습니다. **코어를 바꾸지 않습니다**|

코어가 화면을 모르는 것이 두 가지를 가능하게 합니다 — 화면 없이 리플레이를 돌리는 것과,
연출을 고쳐도 판정 기준이 움직이지 않는 것입니다.

## 코어의 경계

```
core.apply(action) → { state, events[] }
core.snapshotHash() → string
```

이것이 전부입니다. 코어는 시간을 모르고 프레임을 모르고 애니메이션을 모릅니다. **연출이
이벤트 배열을 자기 속도로 재생합니다.**

`snapshotHash()`가 판정의 도구입니다 — 액션 하나마다 해시를 내면 갈라진 지점을 이분해서
찾습니다.

## 웹

|무엇|무엇으로|
|--|--|
|렌더링|**PixiJS v8** — WebGL2, 없으면 WebGL. 커스텀 필터로 에디션 셰이더|
|빌드|Vite + TypeScript|
|데이터 읽기|생성된 `typescript` 산출물 + [`lib/ts/tabbit/tcb_reader.ts`](../../../lib/ts/tabbit/tcb_reader.ts)|
|소리|`WebAudio` 직접. 음높이를 바꾸므로 재생기가 아니라 그래프가 필요합니다|
|세이브|`localStorage`|
|헤드리스|같은 코어를 Node에서 돌립니다. 렌더링을 임포트하지 않습니다|

`tcb_reader.ts`가 `Uint8Array` 위에서 도므로 브라우저에서 그대로 돕니다 — **이 샘플이 그
사실의 첫 사용처입니다.**

데스크탑(Electron)과 안드로이드(Capacitor)는 **같은 웹 빌드를 담습니다.** 코어도 연출도
하나입니다.

## 코어를 한 번만 쓰는 이유

규칙이 데이터에 있으므로 **구현을 늘려서 얻을 것이 없습니다.** 같은 시트를 읽는 두 번째
구현은 같은 값을 낼 뿐이고, 그것을 확인하는 값보다 두 벌을 따라 고치는 값이 큽니다.

코어를 다른 언어로 옮기는 것도 하지 않습니다.

|방법|왜 아닌가|
|--|--|
|WebAssembly 코어|코어는 액션 하나가 0.3~0.6ms이고 계산이 병목이 아닙니다. 연출이 코어 상태를 화면 갱신 중에 계속 읽으므로 **경계에서 드는 변환이 줄이려는 값보다 큽니다** ([성능 규약](performance.md))|
|네이티브 클라이언트|Electron·Capacitor로 닿지 않는 대상이 계획에 없습니다|

## 리플레이 게이트

```
node samples/clover/web/dist/headless.js --replay <파일> --out <결과>
python samples/clover/design-data/tools/verify.py
```

구워 둔 리플레이를 다시 돌려 **해시가 같은지** 봅니다. 코어를 고치지 않았는데 해시가 움직이면
그것이 회귀입니다.

리플레이는 **손으로 만들지 않습니다.** 헤드리스 러너에 무작위 액션을 먹여 완주하는 것을
골라내고, 그것을 파일로 굽습니다([`tools/bake-replays.ts`](../web/tools/bake-replays.ts)).
그러면 리플레이가 코어를 따라 늘어납니다.

|갈래|몇 개|무엇을 덮는가|
|--|--|--|
|완주|5개|안테 8까지. 서로 다른 조커 조합|
|덱마다|8개|덱의 시작 조건이 갈리는 것들|
|스테이크마다|8개|스테이크가 얹는 제약|

**무엇을 구울지는 이미 구워진 것이 정합니다.** 시드와 덱과 스테이크가 파일 안에 있으므로
목록을 따로 들고 있지 않습니다 — 들고 있으면 파일과 어긋납니다.

서버도 같은 코어로 재현합니다. 리더보드는 점수를 받지 않고 리플레이를 받아
[다시 돌려 판정합니다](leaderboard/submission.md).

## 실패의 증상과 원인

|증상|무엇이 잘못되었는가|
|--|--|
|해시가 마지막에만 다릅니다|누적 오차. 만분율 정수 규격을 어긴 곳|
|해시가 특정 액션에서 갈라집니다|그 액션이 쓰는 스트림의 난수 파생|
|리플레이 전부의 해시가 다릅니다|코어의 동작이 바뀐 것입니다. 의도한 변경이면 `npm run bake:replays` 로 다시 굽습니다|
|기계마다 해시가 다릅니다|**언어 표준 난수나 부동소수가 들어간 곳입니다.** 규격은 정수 만분율입니다|
|해시는 같은데 원작과 다릅니다|**데이터의 결함입니다.** 대조표로 돌아갑니다|

마지막 줄이 중요합니다 — **해시가 재현된다는 것은 데이터가 맞다는 뜻이 아닙니다.** 그래서
대조표가 따로 있습니다.
