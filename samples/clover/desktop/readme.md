# clover — 독립 실행

웹 빌드를 그대로 담아 하나의 실행 파일로 냅니다. **게임의 코드는 한 줄도 다르지 않습니다** —
`main.cjs` 의 역할은 창을 하나 띄우고 그 안에 `../web/dist` 를 얹는 것뿐입니다.

```
npm install
npm start                 # 웹을 빌드하고 창을 띄웁니다
npm run dist:win          # 포터블 exe 와 설치본
npm run pack:win          # 압축하지 않은 폴더만 (빠릅니다)
npm run dist:linux        # AppImage
```

## 읽기가 실패할 때

**모든 요청에 응답을 돌려줍니다.** 사설 스킴의 처리기가 예외를 던지면 그 요청은 응답 없이
남아 브라우저가 계속 기다리게 되고, 그 요청이 `index.html` 이면 창 안이 빈 화면으로
남습니다 — 게임이 멈춘 것으로 보입니다. 그래서 없는 파일에는 404, 읽지 못한 것에는 500 을
돌려줍니다.

그래도 페이지를 읽지 못하면 한 번 다시 읽습니다. `render-process-gone` 과 `did-fail-load`
(중단을 뜻하는 `ERR_ABORTED` 는 제외)를 받아 0.4초 뒤에 다시 읽습니다. 게임이 끝나고 새
판으로 넘어갈 때 페이지를 다시 읽는데, 그때 옛 WebGL 문맥이 정리되기 전에 새 문맥이
만들어지면서 렌더러 프로세스가 사라지는 일이 있었습니다. 게임 쪽에서도 넘어가기 전에 연출의
시계를 멈춥니다.

첫 화면이 20초 안에 그려지지 않으면 `index.html` 이 스스로 다시 읽습니다. **두 번까지입니다** —
끝없이 다시 읽으면 그것 자체로 멈춘 것과 같습니다.

산출물은 `out/` 에 나옵니다. **판 번호는 여기 적지 않습니다** — `package.json` 의
`version` 이 그것이고, 베껴 적으면 판을 올린 날부터 없는 파일을 가리킵니다. 실제로
`0.1.0` 인 채로 두 판을 지났습니다.

|무엇|파일|
|--|--|
|한 파일로 실행|`out/clover-<판>-portable.exe`|
|설치본|`out/clover-<판>-setup.exe`|
|압축하지 않은 것|`out/win-unpacked/clover.exe`|

이름의 틀은 `package.json` 의 `build.portable.artifactName` 과 `build.nsis.artifactName`
에 있습니다.

## `file://` 로 열지 않는 이유

게임은 테이블 40개(`.tcb`)와 그림 202장을 `fetch` 로 읽습니다. **크로미움은 `file://` 에서의
`fetch` 를 차단합니다.** 그래서 `clover://` 스킴 하나를 표준 스킴으로 등록하고, 그 스킴의 요청을
빌드 폴더의 파일로 돌려줍니다.

그 덕에 웹에서 쓰는 상대 경로(`./data/Joker.tcb` · `./art/index.json`)가 **고치지 않고 그대로
맞습니다.** 핸들러는 경로를 빌드 폴더 안으로 묶으므로 `..` 로 밖의 파일을 읽지 못합니다.

### 토막을 돌려주어야 하는 이유

**`Range` 를 지원합니다.** 통째로 돌려주고 있었고, `fetch` 로 읽는 테이블과 그림에는 그것으로
충분합니다 — 한 번에 다 읽고 끝나기 때문입니다. **미디어 원소는 다릅니다.** `<video>` 와
`<audio>` 는 `Range` 를 보내고 206 을 기다리며, 그것이 오지 않으면 되감기와 이어 재생을 하지
못합니다.

그래서 데스크탑에서만 이런 일이 있었습니다.

|보이던 것|그 자리|
|--|--|
|판에 들어가면 소리가 없어집니다|곡을 갈아 끼우는 것이 `currentTime = 0` 다음의 `play()` 입니다. 되감기가 되지 않으므로 그 자리에서 멈추고, 앞 곡은 이미 잦아들어 멈춘 뒤입니다|
|환희의 연출이 진행되지 않고 되돌아갑니다|`public/effect/*.mp4` 가 `loop` 로 돕니다. 한 바퀴가 곧 되감기이므로 한 바퀴를 돌지 못합니다|

**모바일은 멀쩡했습니다** — 커패시터가 `http` 로 얹고 그 서버가 토막을 돌려주기 때문입니다.
같은 웹 빌드인데 한쪽만 그러면 **껍데기를 의심합니다.**

확인하는 법은 창 안에서 한 줄입니다. 206 과 `Content-Range` 가 와야 합니다.

```js
await (await fetch('./music/round.ogg', { headers: { Range: 'bytes=0-99' } })).status  // 206
```

**갈래도 손으로 붙입니다.** 응답을 직접 만들면 크로미움이 갈래를 추측하지 않으므로,
확장자마다의 `Content-Type` 이 `main.cjs` 의 `TYPES` 에 있습니다 — 새 갈래의 파일을 담으면
여기 한 줄이 필요합니다.

## 확인

창이 뜨는 것과 그 안이 제대로 그려지는 것은 다른 일입니다. 웹의 `tools/shoot.ts` 와 같은
이유로 여기에도 그림을 굽는 길이 있습니다.

```
node run.cjs --shot ../design-data/out/shot/17-desktop.png
```

**`electron .` 을 직접 부르지 않습니다.** 부모가 일렉트론 앱이면 `ELECTRON_RUN_AS_NODE=1` 이
환경에 붙어 내려오고 — VS Code 처럼 편집기 자체가 일렉트론인 경우가 그렇습니다 — 그 값이
붙은 채로는 창이 아니라 평범한 Node 가 돕니다. `app` 이 `undefined` 가 되어 **창도 뜨지 않고
오류도 없이 0으로 끝납니다.** `run.cjs` 가 그 값을 떼고 띄웁니다.

`npm start` 도 같은 자리를 지나지만 **인자를 넘기지는 못합니다** — `npm start -- --shot x` 는
npm 이 `--shot` 을 자기 것으로 보고 먹습니다. 인자가 있으면 `node run.cjs` 를 직접 부릅니다.

묶은 실행 파일은 이 껍데기를 지나지 않습니다. 일렉트론이 부모인 터미널에서 그것을 돌릴
일이 있으면 그 자리에서 값을 떼야 합니다.

```
$env:CLOVER_SHOT = "../design-data/out/shot/17-desktop.png"
Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
./out/win-unpacked/clover.exe
```

**묶은 것은 환경 변수로 받습니다.** 크로미움이 모르는 `--` 스위치를 우리 코드가 돌기 전에
거절하므로, 인자만으로는 묶은 것을 확인할 길이 없습니다.

세 장이 나옵니다 — 창, 전체 화면, 전체 화면에서 돌아온 뒤. **셋을 다 찍는 이유가 있습니다.**
창 크기가 바뀔 때 배치가 어긋나는 결함이 있었고, 한 장만 찍으면 그것이 드러나지 않습니다.
콘솔에 오류가 하나라도 있으면 1로 끝냅니다.

`--seed CLOVER-0001`(묶은 것은 `CLOVER_SEED`)로 시드를 정할 수 있습니다. 같은 시드는 같은 판이므로 대조할 때 씁니다.

## 조작

|무엇|키|
|--|--|
|전체 화면|`F11`|
|연출 건너뛰기|아무 키|

메뉴 막대는 없앴습니다. 게임 창에 파일 · 편집 메뉴가 있을 이유가 없습니다.

## 아는 한계

- **아이콘이 일렉트론의 기본값입니다.** 브랜드 자산이 들어오면 `build.win.icon` 에 `.ico` 를
  걸면 됩니다.
- **서명하지 않습니다.** `signAndEditExecutable` 을 껐습니다 — 서명 도구를 받는 과정이
  심볼릭 링크를 풀지 못해 실패하고, 이 샘플에 서명이 필요하지 않기 때문입니다. 배포할
  것이라면 인증서를 걸고 그 설정을 되돌립니다.
- **21:9 같은 넓은 화면에서는 좌우가 남습니다.** 판이 1280 × 800 을 기준으로 배치되어 있고,
  남는 자리는 검정이 아니라 배경이 덮습니다. 넓은 화면을 채우려면 배치를 화면 비율에 따라
  바꾸는 작업이 필요하고, 그것은 세로 화면(모바일)과 같은 작업입니다.
