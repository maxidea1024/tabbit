# clover — 안드로이드

웹 빌드를 그대로 담아 APK 하나로 냅니다. **게임의 코드는 한 줄도 다르지 않습니다** —
`desktop/` 이 창을 하나 띄우고 `../web/dist` 를 얹는 것과 같은 얼개이고, 여기서는 그것을
안드로이드 WebView 에 얹습니다.

```
npm install
npm run apk              # 웹 빌드 → 동기화 → 디버그 APK
npm run apk:release      # 서명하지 않은 릴리스 APK
npm run open             # 안드로이드 스튜디오로 열기
```

**윈도우에서는 `:win` 을 붙입니다** — `npm run apk:win` · `npm run apk:release:win`.
래퍼를 부르는 방법이 갈리기 때문입니다: POSIX 셸은 `./gradlew` 라야 현재 폴더의 것을
찾고, `cmd.exe` 는 `./gradlew` 를 알아듣지 못하고 `gradlew` 라야 `gradlew.bat` 를 찾습니다.
**한 줄로 둘 다 되는 표기가 없어서** 두 줄입니다.

**판 번호는 여기 적지 않습니다** — `package.json` 의 `version` 이 그것이고, 베껴 적으면
판을 올린 날부터 없는 파일을 가리킵니다. `desktop/` 의 표가 실제로 그렇게 어긋나 있었습니다.

|무엇|파일|
|--|--|
|디버그|`out/clover-<판>.apk`. 그 자리의 이름은 `android/app/build/outputs/apk/debug/app-debug.apk` 이고, **빌드가 끝나면 저 이름으로 베껴 둡니다** — `app/build.gradle` 이 합니다|
|릴리스(서명 없음)|`out/clover-<판>-release.apk`. 그 자리의 이름은 `android/app/build/outputs/apk/release/app-release-unsigned.apk` 입니다|

## 필요한 것

|무엇|이 기계|
|--|--|
|Android SDK|`%LOCALAPPDATA%\Android\Sdk`. 자리는 `android/local.properties` 에 적고, 그 파일은 기계마다 다르므로 담지 않습니다|
|JDK|17 이상. 21 로 확인했습니다|
|Gradle|따로 깔지 않습니다. `gradlew` 가 받아 씁니다|

## 손댄 것

포장만으로는 게임이 되지 않는 것 둘을 여기서 정합니다.

|무엇|어떻게|
|--|--|
|가로 고정|`AndroidManifest.xml` 의 `screenOrientation="sensorLandscape"`. 판이 1280 × 800 가로 하나에 맞춰 그려지므로 세로로 돌리면 좌우가 잘립니다|
|상태 표시줄|`styles.xml` 에서 상태 표시줄과 내비게이션 바를 반투명으로. 게임 화면에 그것들이 있을 이유가 없습니다|
|진동|`@capacitor/haptics`. **웹 빌드는 이 꾸러미를 담지 않습니다** — 다리의 `Capacitor.nativePromise('Haptics', …)` 로 부르므로, 여기서 깔면 웹 코드를 고치지 않고 네이티브 파형이 됩니다. 깔지 않아도 `navigator.vibrate` 로 떨지만, `VIBRATE` 권한이 이 꾸러미에서 오므로 그때는 조용합니다|

**진동은 폰에서만 있습니다.** 데스크탑에는 진동자가 없으므로 옵션의 「입력」 탭이 아예 서지
않고, 나는 순간은 여섯입니다 — 규격과 그 이유가
[연출](../doc/presentation.md#진동) 에 있습니다.

## 여기서 멈춘 자리

**포장은 됩니다.** 실제 폰(Galaxy S25+)에 설치해 도는 것을 확인하였고, 속도도 문제가
없습니다 — 폰 크기 에뮬레이터에서 하드웨어 GPU로 타이틀과 인게임 모두 60fps 였습니다.

**남은 것은 배치입니다.** 이 판은 마우스와 1280 × 800 화면 하나를 두고 그려졌고, 그것을
손가락과 폰에 옮기는 일은 포장과 다른 일입니다.

|무엇|무엇이 문제입니까|
|--|--|
|글자 크기|**설명 쪽지는 되돌렸습니다**(아래 「고친 것」). 남은 것은 **판 안의 글**입니다 — 「적용 중」 줄 · 상점의 효과 줄 · 태그 딱지의 설명이 폰에서 6~7픽셀입니다. 쪽지처럼 혼자 키울 수 없습니다: 그 글들은 서로의 자리가 정해진 칸 안에 있어서, 키우면 칸을 넘거나 옆의 것을 밀어냅니다|
|화면 비율|판은 16:10 에 맞춰 letterbox 됩니다. 태블릿은 딱 맞지만 폰은 19.5:9 이므로 좌우에 배경이 넓게 남습니다 — 가로의 26%입니다|

이것은 **폰용 배치를 따로 두는 일**입니다. 글자와 여백의 값을 화면 크기로 갈라야 하고,
그것은 이 폴더가 아니라 `web/src/render/theme.ts` 와 `game.ts` 의 일입니다. 지금은 화면
크기로 갈리는 자리가 하나도 없습니다.

## 고친 것

### 손가락

|무엇|어떻게|
|--|--|
|카드가 손가락을 피해 달아나던 것|`beginDrag` 가 누른 자리를 마지막으로 지나간 자리에서 읽고 있었습니다. **마우스는 누르기 전에 움직이지만 손가락은 누르는 그 순간에 처음 나타납니다** — 첫 터치에서는 그 값이 `(0, 0)` 이라 카드가 오른쪽으로 두 배 튀고, 그 튐이 「끌었다」로 읽혀 고르는 것이 되지 않았습니다|
|아주 잘 눌러야 골라지던 것|누른 것과 끈 것을 가르는 거리가 6픽셀이었습니다. 손가락은 가만히 있어도 그보다 흔들립니다 — 터치는 18픽셀로|
|올려놓을 수 없던 것|손가락에는 「올려놓기」가 없습니다. 꾸욱 누르면 설명이 뜹니다 — 조커 · 소모품 · 상점 칸 · 손패가 그 길입니다|
|단추가 작던 것|손가락이 닿는 자리를 키웠습니다. 낼 것과 버릴 것이 112픽셀입니다|
|설명이 너무 작던 것|설명 쪽지가 판의 배율을 되돌려 그립니다 — 화면에서의 크기가 데스크탑과 같습니다. 규격은 [화면의 문법](../doc/ui.md#쪽지와-떠오르는-글) 에 있습니다|

### 껍데기

**게임의 코드가 셋에서 같아야 하는 자리들입니다.** 브라우저 · Electron · 앱에서 뜻이 다른
것은 `web/src/ui/shell.ts` 하나가 맡고, 나머지 코드는 어디서 도는지 모릅니다.

|무엇|무엇이었습니까|
|--|--|
|나가기가 앱 선택 화면을 띄우던 것|끝낼 길을 찾지 못하면 `about:blank` 로 옮겨 가게 두었고, 안드로이드가 그 주소를 받아 「어느 앱으로 열까요」를 띄웠습니다. 지금은 다리의 `App.exitApp` 을 지납니다|
|뒤로 가기가 앱을 물리던 것|**받는 자바스크립트가 없었습니다.** 아무도 받지 않으면 시스템이 가져갑니다 — 판이 떠 있어도 그것을 닫지 않고 통째로 물러났습니다. 지금은 `ESC` 와 같은 자리로 갑니다: 떠 있는 판을 닫고, 없으면 들고 있는 것을 놓고, 그것도 없으면 나갈지 묻습니다|
|첫 터치 전에는 음악이 없던 것|소리 길이 사람의 조작 뒤에만 열리는 것은 브라우저의 규칙이고, 앱의 WebView 는 그 규칙을 끄고 섭니다(`setMediaPlaybackRequiresUserGesture(false)`). 앱에서는 시작할 때 엽니다|
|물러나도 계속 돌던 것|Capacitor 는 WebView 를 멈추지 않습니다. 티커 · 소리 길 · 영상 셋을 함께 멈춥니다|
|화면이 꺼지던 것|판이 도는 동안 `WakeLock` 을 잡습니다. 이 게임에는 시간 제한이 없어서 고르는 사이에 손이 화면에 닿지 않습니다|

### 자원

**손전화에서 앱이 끝나거나 배터리가 줄던 자리입니다.** 규격과 값은
[렌더 성능 규약](../doc/performance.md#자원--메모리와-배터리) 에 있고, `web/tools/check-shell.ts`
가 봅니다.

|무엇|무엇이었습니까|
|--|--|
|그림|상한이 없었습니다. 도감을 끝까지 굴리면 831장이 전부 GPU 에 올라갑니다 — 파일로는 15MB 지만 GPU 에서는 픽셀마다 4바이트입니다. 96MB 로 끊습니다|
|배경음|세 곡을 통째로 풀어 81MB 를 들고 있었습니다. 원소로 흘려 보냅니다|
|프레임|상한이 없어 120Hz 화면에서 초당 120번을 그렸습니다. 60으로 끊습니다|
|그리는 밀도|화면 밀도를 그대로 써서 3이었습니다. 판이 0.6배로 들어가므로 2로 끊습니다|
|글 굽는 밀도|배율이 1보다 작아도 1로 올려 잡아 필요한 것의 2.8배를 굽고 있었습니다|
|저장|액션마다 디스크에 적었습니다. 400ms 로 묶고, 물러날 때는 기다리지 않습니다|
|컨텍스트 회수|구워 둔 것이 빈 채로 돌아왔습니다. 돌아온 자리에서 놓고 다시 굽습니다|
|그림 파일|긴 변 640 이었습니다. 화면에서 가장 크게 쓰이는 자리가 88 × 124 이므로 밀도 상한 3에서도 264 × 372 면 됩니다 — 480 으로 맞췄고 38MB 가 15MB 가 되었습니다|
|보스와 태그의 비율|**정사각이어야 하는데 카드의 비율로 구워져 있었습니다.** 동그라미로 오려 내어 쓰는 그림이라 화면에서 전부 타원이었습니다. 규칙은 `design-data/tools/art.py` 의 `SQUARE` 에 있었는데 굽는 쪽이 그것을 읽지 않았습니다 — 읽게 고쳤고, 이미 구운 것은 가운데를 잘라 256 × 256 으로 맞췄습니다. 그리는 쪽도 비율을 지켜 덮도록 고쳤습니다(`faces.ts` 의 `roundArt`)|
|영상|판을 접어도 넷(11MB)을 들고 있었습니다. 타이틀과 도감에는 나올 자리가 없으므로 놓습니다|
|다시 읽기 감시|물러나 있는 20초만으로 페이지를 다시 읽었습니다. 물러난 동안에는 세지 않습니다|
|구글 백업|저장소에 로그인 표딱지가 있는데 그것이 백업에 담겼습니다. `allowBackup="false"` 입니다|

## 담는 것과 담지 않는 것

`android/` 는 담습니다. 위의 두 손질이 그 안에 있고, 다시 만들면 사라집니다.
**베껴 담은 웹 빌드와 빌드 산출물은 담지 않습니다** — 16MB가 두 벌이 되고, `cap sync` 가
언제든 다시 만듭니다.
