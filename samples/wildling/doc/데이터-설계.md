# 와일드링 — 데이터 설계

[기획서](기획서.md)가 요구하는 것을 테이블과 컬럼으로 옮깁니다. 이 문서가 정하는 것은 셋입니다.

|무엇|어디|
|--|--|
|**무엇을 어떻게 적는가** — 테이블 · 컬럼 · 타입 · 제약|[3](#3-tbs-선언) · [4](#4-테이블-설계)|
|**어느 워크북 어느 탭에 두는가**|[5](#5-워크북과-시트-배치)|
|**어느 기능이 어디에서 쓰이는가**|[6](#6-기능-배치표)|

> **표기는 주 레이아웃(`tabbit`)의 확정본을 따릅니다.** 근거는
> [주 레이아웃](../../../spec/primary-layout.md)과 [다형과 참조 배열](../../../spec/polymorphism.md)이고,
> 이 문서는 그 표기를 **쓰는 쪽**입니다. 표기를 새로 정하지 않습니다.

---

## 1. 설계 원칙

|#|원칙|근거|
|--|--|--|
|1|**시트 하나에 엔티티 하나.** 탭 이름이 엔티티 이름입니다|엑셀의 정렬 · 필터가 표 하나에만 걸립니다. 헤더가 데이터 사이로 흩어지는 사고가 줄어듭니다|
|2|**필드만 `snake`, 나머지는 전부 `pascal`**|시트에서 「타입과 이름의 자리」와 「값이 들어가는 자리」가 눈으로 구분됩니다. `Naming.OnViolation`을 `error`로 두어 검사로 강제합니다|
|3|**반복되는 값 묶음은 `.tbs`에 선언**|같은 멤버 조합을 테이블마다 다시 적지 않습니다|
|4|**형태가 행마다 다른 것은 다형 레코드**|참조는 컬럼당 대상 하나이므로, 「아이템이거나 재화이거나 와일드링」을 참조로 표현할 수 없습니다|
|5|**밸런스 값은 `.tsv`에, 시트는 저작기가 생성**|숫자 조정이 diff로 읽힙니다. 워크북은 `.tsv` + 레이아웃 선언의 산출물입니다|

### 1.1 예외 2곳 — 원칙 1을 지키지 않는 자리

경계 판정과 다중 엔티티 배치는 그 배치를 실제로 하지 않으면 검증되지 않습니다. 억지 시트를
만들지 않고 자연스러운 자리 2곳에 둡니다.

|탭|배치|
|--|--|
|`Const_Battle`|상수셋 `BattleConst`와 그것만 쓰는 작은 표 `ElementAffinityColumn`을 나란히|
|`Const_Growth`|상수셋 `GrowthConst` 아래에 빈 행 하나를 두고 `AwakeningConst`|

## 2. 키와 참조

### 2.1 키 타입

**문자열 키를 씁니다.** `sprout_deer_1`처럼 읽을 수 있는 id여야 시트에서 참조를 눈으로
검증할 수 있고, 밸런스 `.tsv`의 diff도 읽힙니다. 수치 id는 `Stage.index`처럼 순번이 뜻을
갖는 자리에만 씁니다.

### 2.2 키 선언

|테이블|`key` 메타|무엇을 확인하는가|
|--|--|--|
|`Monster`|(생략)|첫 필드 컬럼이 기본 인덱스인 기본 동작|
|`Item`|`key=item_id`|**첫 컬럼이 아닌 컬럼**을 기본 인덱스로 지정하는 것. `Item`의 첫 컬럼은 `category`입니다|
|`Stage`|`key="stage_id; region_id,index"`|첫 키는 단일(참조 대상이 되므로), 둘째가 **복합 보조 키**|
|`RegionYield`|`key="region_id,hour_band"`|**복합 기본 인덱스.** 조회가 다인자가 되고, 이 테이블은 `foreign`의 대상이 될 수 없습니다|
|`Monster`|`*display_code`|**컬럼 자리의 보조 키.** 운영 도구가 쓰는 짧은 코드입니다|

`RegionYield`가 복합 기본 인덱스인 것은 의도한 배치입니다 — 복합 키 테이블이 참조 대상이 될
수 없다는 규칙이 이 데이터에서 실제로 걸리는지 확인하는 자리이고, 그래서 이 테이블을 가리키는
컬럼을 두지 않았습니다.

### 2.3 참조 · 검사 · 다형의 구분

|데이터의 성질|적는 법|이 데이터에서|
|--|--|--|
|대상이 테이블 하나|`foreign X`|`MonsterSkill.skill_id foreign Skill`|
|같은 테이블의 키 목록|`foreign X[]`|`Stage.wave_monster_ids foreign Monster[]`|
|값이 어느 테이블의 id이기만 하면 됨|`int (refs=A;B)`|`Mission.target_id`|
|형태가 행마다 다르고 id를 줄 가치가 없음|다형 레코드 `$type`|`RewardEntry.reward`|
|개수도 형태도 행마다 다름|다형 레코드 + 멀티 로우|`Boss.effects[]`|

`Mission.target_id`가 검사인 이유는 **행에 닿을 필요가 없기** 때문입니다. 의뢰 조건은
「`sprout_deer_1`을 3회 발견」이고, 클라이언트는 그 id를 표시에만 쓰므로 대상 행을 조회하지
않습니다. 참조로 두면 대상 목록을 컬럼 하나에 담을 수 없으므로 컬럼을 3개로 나누어야 하고,
그것은 이 자리에 맞지 않습니다.

## 3. `.tbs` 선언

`samples/wildling/schemas/` 아래에 3개 파일로 나눕니다. recipe의 `Schemas`가 그 디렉터리를
가리킵니다.

|파일|담는 것|
|--|--|
|`common.tbs`|`StatBlock` · `Cost` · `EncounterEntry`|
|`reward.tbs`|`Reward`와 변종 4개, `Requirement`와 변종 4개|
|`battle.tbs`|`Effect`와 변종 4개, enum 4개|

### 3.1 `common.tbs`

```
/// 와일드링과 수호자가 공유하는 능력치 묶음.
struct StatBlock
    /// 체력.
    field hp         int (min=1)
    /// 공격.
    field attack     int (min=1)
    /// 방어.
    field defense    int (min=0)
    /// 행동 순서. 같으면 배치 순서가 정합니다.
    field speed      int (min=1)
    /// 치명타 확률. 만분율.
    field crit_rate  int (min=0, max=10000)
    /// 치명타 배수. 만분율. 10000이 1배입니다.
    field crit_power int (min=10000)

/// 재화 하나를 얼마나 소모하는가. 셀 하나에 `gold,4400`으로 적습니다.
struct Cost (sep=",")
    /// 어느 재화인가.
    field currency_id foreign Currency
    /// 수량.
    field amount      int (min=1)

/// 출현 목록의 한 항목.
struct EncounterEntry
    /// 어느 단계가 나오는가.
    field monster_id     foreign Monster
    /// 가중치. 등급 기본값에 지역 계수를 적용한 값입니다.
    field weight         int (min=1)
    /// 어느 슬롯에서 나오는가.
    field encounter_slot EncounterSlot
```

`Cost`에 `sep`을 두는 것이 이 파일의 요점입니다 — 같은 타입을 **셀 하나로 적는 벌**과
**멤버를 컬럼으로 펼친 벌**이 둘 다 있고, 와이어가 같습니다 ([6.3](#63-같은-타입-두-표기)).

### 3.2 `reward.tbs`

```
/// 무엇을 얼마나 주는가. 변종이 대상 카탈로그를 정합니다.
abstract struct Reward
    /// 수량. 모든 변종이 갖습니다.
    field amount int (min=1)

/// 아이템을 준다.
struct ItemReward extends Reward @1
    field item_id     foreign Item

/// 재화를 준다.
struct CurrencyReward extends Reward @2
    field currency_id foreign Currency

/// 와일드링을 준다. 수호자 격파 보상이 이것입니다.
struct MonsterReward extends Reward @3
    field monster_id  foreign Monster

/// 울림 조각을 준다. 대상 종의 조각입니다.
struct ShardReward extends Reward @4
    field monster_id  foreign Monster

/// 무엇이 충족되어야 하는가.
abstract struct Requirement

/// 그 개체의 레벨.
struct LevelRequirement extends Requirement @1
    field level       int (min=1, max=70)

/// 기록부의 상태.
struct CodexRequirement extends Requirement @2
    field codex_state CodexState

/// 아이템 보유.
struct ItemRequirement extends Requirement @3
    field item_id     foreign Item
    field amount      int (min=1)

/// 스테이지 클리어.
struct StageRequirement extends Requirement @4
    field stage_id    foreign Stage
```

- **`Reward`의 `amount`가 기반에 있습니다.** 와이어에서 컬럼 하나이고 모든 행에 값이
  있습니다. 변종마다 복제하면 컬럼이 4개가 되고 그중 하나만 채워집니다.
- **`MonsterReward`와 `ShardReward`가 `monster_id`를 공유합니다.** 같은 이름 · 같은 타입이므로
  컬럼 하나입니다. 이름을 `shard_monster_id`로 달리 두면 컬럼이 2개가 되고, 시트가 넓어집니다.
- **`Requirement`는 기반에 필드가 없습니다.** 그 형태도 지원되는지 확인하는 자리입니다.
- 판별자 `@N`을 전부 명시합니다. 선언 순서에 묶이면 변종을 재배열할 때 배포된 리더가 다른
  변종으로 읽습니다.

### 3.3 `battle.tbs`

```
/// 스킬 하나가 일으키는 것.
abstract struct Effect
    /// 발동 확률. 만분율. 10000이 항상입니다.
    field chance int (min=1, max=10000)

/// 피해.
struct DamageEffect extends Effect @1
    /// 공격력에 적용하는 배수. 만분율.
    field power     int (min=1)

/// 회복.
struct HealEffect extends Effect @2
    /// 회복량에 적용하는 배수. 만분율.
    field power     int (min=1)

/// 상태 부여.
struct StatusEffect extends Effect @3
    field status    StatusKind
    /// 지속 턴.
    field duration  int (min=1, max=9)

/// 능력치 변동.
struct BuffEffect extends Effect @4
    field stat      StatKind
    /// 변동률. 만분율. 음수는 하락입니다.
    field ratio     int
    field duration  int (min=1, max=9)

/// 속성.
enum Element
    /// 잎새에 강하고 물결에 약합니다.
    value Flame  = 1
    value Tide   = 2
    value Leaf   = 3
    /// 물결과 잎새에 강하고 그늘에 약합니다.
    value Arc    = 4
    /// 번개에 강하고 약한 상대가 없습니다.
    value Umbra  = 5

/// 희소성. 종의 성질이고 변하지 않습니다.
enum Grade
    value Common    = 1
    value Rare      = 2
    value Epic      = 3
    value Legendary = 4
    value Mythic    = 5

/// 기록부의 상태.
enum CodexState
    value Unknown  = 0
    value Sighted  = 1
    value Recorded = 2
    value Studied  = 3

/// 능력치의 종류. `BuffEffect`가 가리킵니다.
enum StatKind
    value Attack    = 1
    value Defense   = 2
    value Speed     = 3
    value CritRate  = 4
```

**enum을 `.tbs`와 시트에 반씩 둡니다.** `.tbs`에 두는 것은 `Effect` · `Requirement` 변종이
멤버 타입으로 쓰는 것들입니다 — 선언이 같은 파일에 있어야 읽는 사람이 한 번에 봅니다.
나머지(`Role` · `EncounterSlot` · `StatusKind` · `RegionState` · `MissionCycle` ·
`ItemCategory`)는 시트 탭에 둡니다. **양쪽이 다 있어야 두 표기가 다 검증됩니다.**

## 4. 테이블 설계

컬럼 표기는 `:field` / `:type`의 쌍으로 적습니다. `:desc`와 `:target`은 생략해 적었고,
실제 시트에는 전부 있습니다.

### 4.1 와일드링

#### `Monster` — 종의 한 단계

|`:field`|`:type`|비고|
|--|--|--|
|`monster_id`|`string`|기본 인덱스|
|`*display_code`|`string (regex="^[a-z]{2}[0-9]{3}$")`|보조 키. 운영 도구용|
|`species_id`|`string`|같은 종을 묶습니다|
|`stage`|`int (min=1, max=3)`||
|`name`|`string (text=Monster)`|번역 수집|
|`description`|`string (text=Monster, namespace=Codex)`|기록부 설명|
|`element`|`Element`|`.tbs` 선언|
|`grade`|`Grade`|`.tbs` 선언|
|`role`|`Role`|시트 enum|
|`base.hp` … `base.crit_power`|`StatBlock`|**첫 멤버 컬럼에만** 타입 기재|
|`habitat`|`bitset`|서식 지역 플래그. `0b10011`|
|`max_stage`|`int (min=1, max=3)`||
|`icon`|`string (asset=icon)`|`:target` `c`|
|`model_offset`|`vec3f?`|`:target` `c`. 연출 보정|
|`tags`|`string[]`|셀 배열. 검색 태그|
|`#old_grade@7`|—|묘비. 등급을 종 단위로 옮기기 전의 컬럼|
|`#`|—|메모 컬럼|

- `habitat`을 `bitset`으로 두는 것은 지역이 5개이고 한 종이 여러 지역에 나타나기 때문입니다.
  `foreign Region[]`으로도 적을 수 있지만, 기록부 화면이 「이 종이 나오는 지역」을 플래그
  비교로만 쓰므로 참조가 필요하지 않습니다.
- `model_offset`이 옵셔널인 것은 대부분의 종이 보정을 쓰지 않기 때문입니다.

#### `MonsterSkill` — 단계별 사용 가능 스킬

|`:field`|`:type`|
|--|--|
|`monster_id`|`foreign Monster`|
|`skill_id`|`foreign Skill`|
|`slot_kind`|`SlotKind`|
|`unlock_stage`|`int (min=1, max=3)`|

기본 인덱스가 `monster_id`이고 같은 값이 여러 행에 나타나므로, **`key="monster_id,skill_id"`
복합 기본 인덱스**로 둡니다. 이 테이블은 참조 대상이 아니므로 복합 키 제약에 걸리지 않습니다.

#### `MonsterAwakening` — 각성 관계

|`:field`|`:type`|비고|
|--|--|--|
|`from_monster_id`|`foreign Monster`|기본 인덱스|
|`to_monster_id`|`foreign Monster`|같은 테이블을 가리킵니다|
|`gain.hp` … `gain.crit_power`|`StatBlock`||
|`requirements[].$type`|`Requirement`|**멀티 로우 다형 배열**|
|`requirements[].level`|—|합집합 컬럼|
|`requirements[].codex_state`|—||
|`requirements[].item_id`|—||
|`requirements[].amount`|—||
|`requirements[].stage_id`|—||
|`costs[]`|`Cost`|셀 하나에 `shard,30`|

`requirements`가 이 데이터에서 **다형 배열의 정본**입니다. 조건 개수가 종마다 2~4개이고
형태가 갈립니다.

### 4.2 전투

#### `Skill`

|`:field`|`:type`|비고|
|--|--|--|
|`skill_id`|`string`||
|`name`|`string (text=Skill)`||
|`description`|`string (text=Skill)`||
|`element`|`Element?`|무속성 스킬은 빈 칸|
|`target_scope`|`TargetScope`|시트 enum|
|`cooldown`|`int (min=0, max=9)`||
|`icon`|`string (asset=icon)`|`:target` `c`|
|`effects[].$type`|`Effect`|**멀티 로우 다형 배열**|
|`effects[].chance`|—|기반 필드|
|`effects[].power`|—|`DamageEffect` · `HealEffect` 공유|
|`effects[].status`|—||
|`effects[].stat`|—||
|`effects[].ratio`|—||
|`effects[].duration`|—|`StatusEffect` · `BuffEffect` 공유|

컬럼이 **모든 변종의 합집합**이고, 같은 이름 · 같은 타입인 `power`와 `duration`이 컬럼을
공유합니다. 변종 4개의 멤버 합계는 8개인데 컬럼은 6개입니다.

#### `SkillGrowth`

|`:field`|`:type`|
|--|--|
|`skill_id`|`foreign Skill`|
|`level`|`int (min=1, max=10)`|
|`power_factor`|`int (min=10000)`|
|`costs[0]` `costs[1]`|`Cost`|

`key="skill_id,level"` 복합 기본 인덱스입니다. `costs`가 **원소 번호 칸**이므로 배열의 세
표기 중 두 번째입니다 — 타입은 원소 0에만 적습니다.

#### `ElementAffinity` — 매트릭스 표

|`:field`|`:type`|
|--|--|
|`attacker`|`Element`|
|`1` `2` `3` `4` `5`|`int`|

**컬럼 이름이 정수여야 매트릭스로 판독됩니다.** 그래서 방어 속성 축은 이름이 아니라 `Element`
enum의 값입니다. 값은 만분율 배수이고, 유리는 `13500`, 불리는 `7500`, 그 외는 `10000`입니다.

산출물은 배열 컬럼 하나와 **컬럼 테이블** `ElementAffinityColumn`입니다. 두 테이블은 같이
배포해야 합니다 — `at`이 자리이지 id가 아니고, 컬럼이 중간에 추가되면 뒤가 밀립니다.

> **자르기를 걸 수 없는 자리입니다.** 매트릭스에서 뒤를 자르면 행마다 배열 길이가 달라지고
> `value[at]`이 성립하지 않습니다. `TrimTrailingArrayElements`를 이 소스에서 켜지 않는
> 이유이기도 합니다.

#### `Boss`

### 4.5 보상과 조건 — 항목 테이블로의 분리

**다형 레코드를 배열로 두지 않고 테이블 하나로 내립니다.** 그러면 판별자가 스칼라 그룹이 되고,
멀티 로우와 판별자의 조합([8.1](#81-멀티-로우와-판별자의-조합))을 기다리지 않습니다. 정규화로도
이쪽이 맞습니다 — 같은 보상 묶음을 여러 테이블이 가리키므로 묶음에 id가 필요합니다.

#### `RewardGroup` · `RewardEntry`

|테이블|`:field`|`:type`|
|--|--|--|
|`RewardGroup`|`reward_group_id`|`string`|
||`note`|`string?`|
|`RewardEntry`|`reward_group_id`|`foreign RewardGroup`|
||`order`|`int (min=0, max=15)`|
||`reward.$type`|`Reward`|
||`reward.amount`|—|
||`reward.item_id`|—|
||`reward.currency_id`|—|
||`reward.monster_id`|—|
||`rate`|`int (min=1, max=10000)`|
||`server_weight`|`int?` · `:target` `s`|

`RewardEntry`는 `key="reward_group_id,order"`이므로 참조 대상이 되지 않습니다. 가리켜야 하는
것은 묶음이고, 그 자리가 `RewardGroup`입니다.

**`Reward`를 쓰는 8곳이 컬럼 하나로 줄어듭니다** — `reward_group_id foreign RewardGroup`입니다.
`DropTable` · `StageReward` · `CodexReward` · `Mission` · `AdReward` · `PassBenefit` ·
`ShopSlot` · `Package`가 그 컬럼을 갖고, 합집합 컬럼 5개는 `RewardEntry` 한 곳에만 있습니다.
`.tbs` 선언의 효과가 사라진 것이 아니라 **한 자리로 모인 것**입니다.

### 6.3 같은 타입, 두 표기

`Cost`가 세 자리에 서로 다른 표기로 나타납니다. **와이어는 셋 다 같습니다.**

|자리|표기|셀에 적히는 것|
|--|--|--|
|`MonsterAwakening.costs[]`|멀티 로우 + `sep`|`shard,30`|
|`SkillGrowth.costs[0]` `[1]`|원소 번호 칸 + `sep`|`gold,1200`|
|`GrowthCurve.costs[0].currency_id` `[0].amount`|원소 번호 칸 + 멤버 펼침|`gold` / `4400`|

세 번째가 `sep`을 쓰지 않고 멤버를 컬럼으로 펼친 벌입니다. **같은 `.tbs` 선언을 두 방식으로
읽는 것**이 확인되는 자리입니다.

|데이터베이스 타깃 4종|서버가 필요합니다. 회귀 스위트가 컨테이너로 확인합니다|
|히스토리 · `--serve`|실행이 필요합니다|
|`rescue` · `named-range` 레이아웃|그쪽 샘플의 몫입니다|
|전 언어 타깃|`samples/rescue/out/`이 이미 그 답입니다|
|`json` · `text` · `html` · `summary` 타깃|**최종 확인 지점이 유니티**이므로 코드 생성은 `csharp` 하나입니다. 값을 눈으로 볼 자리는 유니티의 확인 씬이고, 나머지 타깃은 `rescue`가 이미 냅니다|
|`set` · `map`|이름과 함께 거절됩니다. 거절 결과를 대조표에 싣습니다|
|변종의 묘비|표기가 아직 없습니다|
|`$key` · `$value`|아직 지원하지 않습니다|
|중첩 멀티 로우|1차 거절 대상입니다|
|`TrimTrailingArrayElements`|`ElementAffinity`가 있어 이 소스에서 켤 수 없습니다|

## 7. 검증 규칙

시트로 표현할 수 없는 규칙입니다. `samples/wildling/validation/rules/` 아래에 둡니다.

|단계|규칙|무엇|
|--|--|--|
|`pre`|`InputsRules`|`.tsv` 원본과 워크북의 행 수 일치|
|`tables`|`MonsterRules`|`species_id` + `stage`의 유일성. `max_stage`와 실제 각성 사슬의 일치|
|`tables`|`MonsterAwakeningRules`|**각성 후 능력치가 직전 단계 상한보다 높은지** ([기획서 §7.3](기획서.md))|
|`tables`|`StageRules`|`wave_monster_ids`와 `wave_levels`의 길이 일치|
|`tables`|`EncounterTableRules`|지역마다 고유 종 4종 이상, 은둔 슬롯 1종|
|`tables`|`DropTableRules`|확률 합이 10000을 넘지 않는지|
|`tables`|`MissionRules`|`target_id`가 `cycle`에 맞는 카탈로그를 가리키는지|
|`global`|`ProgressionRules`|**각성 재료가 2개 지역 이상에서 산출되는지** ([기획서 §10.4](기획서.md))|
|`global`|`ConventionsRules`|`text` 컬럼의 빈 값, 아이콘 이름 규약|
|`runtime`|—|이 샘플에는 없습니다. 연결이 필요한 규칙이 없습니다|

`MonsterAwakeningRules`와 `ProgressionRules`가 이 규칙 집합의 요점입니다 — 둘 다 기획서가
정한 것이고, 타입으로는 표현되지 않으며, 어긋나면 게임이 성립하지 않습니다.

### 8.1 멀티 로우와 판별자의 조합

**멀티 로우 자체는 구현되어 있습니다** — 주 레이아웃 2단계이고, 같은 배열을 `[n]`과 `[]`로 적은
`.tcb`가 바이트 동일함까지 확인되어 있습니다. 남은 것은 **멀티 로우와 판별자의 조합**이고
([다형과 참조 배열 §11](../../../spec/polymorphism.md)의 5단계), 현재 픽스처는 `Effect.$type`
스칼라 그룹 하나입니다.

[4.5](#45-보상과-조건--항목-테이블로의-분리)가 그 조합을 요구하지 않도록 보상과 조건을
테이블로 내렸습니다. **그래서 이 데이터는 지금 표기로 전량 변환됩니다.**

조합이 남는 자리를 **하나만** 둡니다 — `Boss.effects[]`입니다. 수호자의 특수 능력은 수호자
하나에만 종속되고 공유되지 않으므로 묶음 id를 줄 가치가 없고, 그래서 그 표기가 요구되는 자리의
예로 정확합니다. 5단계가 들어올 때까지 이 컬럼은 거절되므로, `recipe.jsonc`에서 `Boss`를
`ExcludeSheets`로 빼고 5단계와 함께 되돌립니다.

### 8.2 조합이 아닌 멀티 로우의 자리

조합이 아닌 멀티 로우는 이 데이터에도 있습니다.

|테이블|컬럼|
|--|--|
|`EncounterTable`|`entries[].monster_id` — `EncounterEntry` struct 그룹|
|`MonsterAwakening`|`costs[]` — `sep`을 쓴 `Cost`|

`EncounterTable`은 멀티 로우 그룹이 하나가 되었습니다 — 조건은 `requirement_group_id`로
옮겼습니다.
