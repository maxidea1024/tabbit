# Tabbit

**Game Data Authoring & Build Tool**

[![license](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

게임의 정적 데이터를 작성하고, 검증하고, 런타임 데이터로 빌드합니다.

아이템, 스테이지, 밸런스, 설정과 같은 정적 데이터는 게임의 근간입니다.
코드보다 자주 바뀌고, 더 많은 사람이 수정하며, 잘못된 값은 문제가 발생한 뒤에야 발견되기 쉽습니다.

Tabbit은 이 데이터를 **작성하고 → 검증하고 → 분석하고 → 최적화하고 → 런타임 데이터로 빌드하는** 도구입니다.

| 단계 | 하는 일 |
| --- | --- |
| **Author** | 엑셀·구글 스프레드시트에 테이블, enum, 상수셋을 작성합니다. |
| **Schema** | 시트에서 타입, 인덱스, 참조, 제약을 읽어 스키마를 구성합니다. |
| **Validate** | 타입만으로 표현할 수 없는 규칙까지 C#으로 검증합니다. 오류가 발생한 셀도 함께 알려줍니다. |
| **Analyze** | 생성된 데이터를 HTML로 확인하고, 커밋 사이의 변경을 셀 단위로 추적합니다. |
| **Optimize** | 컬럼의 데이터 특성에 맞춰 사전, RLE, 델타, 비트폭 패킹 등의 인코딩을 선택합니다. |
| **Build** | 런타임 바이너리와 이를 읽는 코드를 지원하는 언어별로 생성합니다. |

엑셀과 구글 스프레드시트는 **입력 수단**일 뿐입니다.

지금 데이터가 그곳에 있기 때문에 읽는 것입니다.
Tabbit의 핵심은 무엇을 읽느냐가 아니라 **무엇을 만들어 내느냐**에 있습니다.

## 빠른 시작

현재는 [소스에서 직접 빌드합니다](doc/install.md#소스에서-빌드하기).

릴리즈가 제공되면 실행 파일을 내려받는 것만으로 충분합니다.
.NET 런타임도 별도로 설치할 필요가 없습니다.

```bash
tabbit --new-recipe my-recipe.json --template unity
tabbit --recipe my-recipe.json
```

`recipe` 파일에 데이터를 **어디서 읽고 어디로 출력할지** 정의합니다.

`--template`은 시작하려는 환경에 필요한 설정을 생성합니다.

```text
unity
client-server
server
web
unreal
ci
```

각 설정에는 왜 필요한지 설명하는 주석도 함께 들어갑니다.

생성된 코드는 프로젝트에서 바로 사용할 수 있습니다.

```csharp
await GameData.ReadAllAsync("./data");

var sword = GameData.Item.FindByIndex(1);
```

접근자 이름과 코드 스타일은 각 언어의 관례를 따릅니다.

시트 한 장이 실제 코드로 어떻게 변하는지는 [시트에 무엇을 적을 수 있나](doc/concepts.md)에서 처음부터 끝까지 따라볼 수 있습니다.

그 다음에는 [CLI](doc/cli.md)와 [Recipe 파일](doc/recipe.md)을 확인하면 됩니다.

| --- | --- |
| **Export** | Binary, JSON, Text |
| **Database** | MySQL, PostgreSQL, MongoDB, Redis |

## TCB

**TCB — Tabbit Compiled Binary**

Tabbit의 런타임 데이터 형식입니다.

TCB는 런타임에서 다시 파싱하지 않습니다.
값의 크기에 맞춰 인코딩하고, 스키마가 달라졌을 때 조용히 잘못 읽는 것을 허용하지 않습니다.

읽을 수 있으면 정확하게 읽고, 읽을 수 없으면 멈춥니다.

오류가 발생하면 필드 이름과 양쪽 타입을 함께 보여주므로, 스키마 변경으로 인한 문제를 빠르게 찾을 수 있습니다.

자세한 내용은 [바이너리 형식](doc/binary-format.md)에서 확인할 수 있습니다.

## 왜 Tabbit을 쓰나

### 데이터 문제를 빌드 단계에서 찾습니다

단순한 타입 오류부터 참조 관계, 범위, 중복, 프로젝트의 비즈니스 규칙까지 검증합니다.

시트에 표현할 수 없는 규칙은 [C#으로 작성](doc/validation.md)할 수 있습니다.

검증 오류는 단순한 메시지가 아니라 **문제가 발생한 셀까지 연결해서 보여줍니다.**

구글 스프레드시트라면 링크를 눌러 해당 셀로 바로 이동할 수 있습니다.

### 검증 결과를 기록합니다

실행할 때마다 HTML 보고서를 남깁니다.

신규 오류인지, 계속 남아 있는 오류인지, 이전에 있던 문제가 해결되었는지도 구분합니다.

경고 이상의 문제가 발생하면 보고서를 바로 확인할 수 있습니다.

### 잘못된 데이터는 결과물로 나가지 않습니다

검증은 모든 출력보다 먼저 수행됩니다.

검증에 실패한 실행은 바이너리에도, 데이터베이스에도 결과를 남기지 않습니다.

새 결과가 완전히 준비된 뒤 한 번에 교체하므로, 중간에 빌드가 실패해도 이전 결과는 그대로 사용할 수 있습니다.

### 모든 언어가 같은 데이터를 읽습니다

하나의 TCB 포맷을 정의하고, 각 언어에 맞는 리더를 생성합니다.

하나의 회귀 테스트에서 데이터를 작성하고 각 언어로 읽어 결과를 비교할 수 있습니다.

언어가 달라도 같은 데이터를 읽는다는 것을 지속적으로 검증할 수 있습니다.

### 변경되지 않은 데이터는 다시 만들지 않습니다

이전 실행에서 무엇을 읽고 무엇을 생성했는지 기록합니다.

변경 사항을 비교해 필요한 작업만 수행합니다.

전체 빌드가 필요한 경우에는 **왜 전체 빌드가 필요한지도 함께 출력합니다.**

### 기존 시트를 강제로 고칠 필요가 없습니다

Tabbit의 규칙에 맞춰 새 시트를 처음부터 만들 필요는 없습니다.

기존에 작성해 둔 시트도 읽을 수 있습니다.

먼저 데이터를 옮기고, 필요한 부분부터 점진적으로 Tabbit의 기능을 적용할 수 있습니다.

기능 전체는 [기능](doc/features.md)에 정리되어 있습니다.

## 기여하기

버그와 제안은 [이슈](https://github.com/maxidea1024/tabbit/issues)로 알려주세요.

가능하면 **어떤 데이터를 사용했고, 어떤 명령을 실행했으며, 무엇이 발생했는지** 함께 적어주세요. 문제를 재현하는 데 가장 큰 도움이 됩니다.

생성기나 템플릿을 수정했다면 골든 데이터를 다시 기록하고 diff를 확인해 주세요.

개발과 테스트 방법은 [아키텍처와 개발](doc/architecture.md)에서 확인할 수 있습니다.

보안 문제는 공개 이슈가 아닌 [SECURITY.md](SECURITY.md)의 절차를 따라주세요.

변경 내역은 [CHANGELOG.md](CHANGELOG.md)에서 확인할 수 있으며, 사용하는 외부 패키지는 [의존 패키지](doc/dependencies.md)에서 확인할 수 있습니다.
