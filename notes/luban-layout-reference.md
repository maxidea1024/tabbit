## 1. 시트 인식, 방향, 파일 형식

### 1.1 A1 셀에 의한 시트 선별

- **A1 셀이 `##`으로 시작하지 않는 시트는 통째로 무시**됩니다. 한 워크북 안에 유효 시트가
  하나도 없으면 오류입니다. [SLU `TryParseMeta`]
- A1은 **메타 셀**입니다. `##` 뒤에 `#`로 구분된 속성이 옵니다. 허용 키는 `+` · `var` ·
  `comment` · `type`(무동작, 표식용) · `column` · `vertical`(세로표)이고, **그 외 키가 A1에
  오면 예외**입니다. [SLU:404-449]
- 구분자는 `#`입니다. 과거의 `&`는 금지되어 있고 발견 시 예외를 던집니다. [SLU:188-191]
- 시트 이름 자체에는 규약이 없습니다. 선택은 A1 마커와 `sheet@file` 지정으로만 합니다(§9).
- **파일 형식** — `xls` · `xlsx` · `xlsm` · `xlm` · `csv`. CSV는 인코딩을 자동 감지합니다.

### 1.2 가로표(기본)와 세로표(전치)

- 기본은 한 행 = 한 레코드입니다.
- A1이 `##column` 또는 `##vertical`이면 **읽기 전에 행렬 전체를 전치**하고, 이후의 모든
  규칙(헤더 행, 무시 행·열, 멀티 로우)을 전치된 격자에 동일하게 적용합니다.
  [SLU:436-441, 547-566] 세로표에서는 「한 열 = 한 레코드」가 됩니다.
- datable.cn(vertical-and-sep)의 세로표 예시:

|A|B|C|
|--|--|--|
|`##column`|`##type`|*(빈 칸)*|
|bag_init_size|int|20|
|bag_max_size|int|100|

전치 후 1행이 역사적 호환 규칙(§2.1)에 의해 타이틀 행으로 인정되고, 2행이 타입 행,
3행부터가 데이터입니다. 문서 원문은 값 열 최상단에 `##`을 그려 놓았는데, 전치 후 첫 셀이
`##`인 행은 데이터에서 제거되므로 **소스 기준으로 문서 그림이 부정확합니다**(§13).

## 2. 헤더 행(`##` 마커)

### 2.1 행 태그 전체 목록

첫 셀이 `##`으로 시작하는 상단 행들이 헤더 블록입니다. 알려진 행 태그는 소스에 하드코딩되어
있습니다 — `var` · `+` · `type` · `desc` · `comment` · `column` · `group` [SLU:95-104].
**모르는 태그(오타)는 오류 로그만 남기고 중단하지 않습니다** [SLU:125-133].

|행|역할|필수 여부|
|--|--|--|
|`##var` (동의어 `##field` · `##+`)|필드명 행. 각 셀 = 필드 이름(+이름 속성)|필수(아래 예외)|
|`##type`|필드 타입 행. `define_from_file`(§5)일 때만 소비, 스키마가 따로 있으면 주석 행|define_from_file이면 필수|
|`##group`|필드별 내보내기 그룹(c · s 등). define_from_file일 때 소비|선택|
|`##desc` → `##comment` → 2번째 이후의 맨몸 `##`|사람용 설명 행. 이 우선순위로 하나를 찾아 필드 주석으로 사용|선택|
|`##` (맨몸)|범용 주석 행. 단 1행에 오면 역사적 호환으로 필드명 행 취급|선택|
|`##column` / `##vertical`|A1 전용 메타. 세로표 선언|선택|

- **개수 제한 없음** — `##var` 행은 중첩 깊이만큼 여러 개 올 수 있습니다(§3). 헤더 행
  순서는 자유이고, 필드명 행은 태그 검색으로 찾습니다. 단 A1 태그 제약(§1.1) 때문에
  `##group` · `##desc`는 1행에 둘 수 없습니다.
- **역사적 호환 규칙** — 1행의 태그가 비어 있거나 `column`뿐이면 그 행을 필드명 행으로
  인정합니다. 그래서 고전 레이아웃 「1행 `##`+필드명, 2행 `##type`」이 성립합니다.
- **데이터 행 판정** — 헤더 파싱 후, 첫 셀이 `##`으로 시작하는 모든 행과 완전 빈 행을
  제거한 나머지가 데이터입니다. `##…` 행은 데이터 한가운데 있어도 주석 행입니다.
- 연속 빈 행 300개 초과 시 성능 경고만 냅니다.

### 2.2 최소 예시 (datable.cn/basics)

|A|B|C|D|E|
|--|--|--|--|--|
|`##var`|id|name|price|on_sale|
|`##type`|int|string|int|bool|
|`##group`|c,s|c|c| |
|`##`|도구ID|이름|가격|판매중|
| |1001|금화|0|1|

A열은 헤더 행에서는 행 태그, 데이터 행에서는 레코드 태그 칸(§4)입니다. 데이터의 빈 행
판정에서 A열은 세지 않습니다 [RCS:212-223].

### 2.3 필드명 셀의 문법

`##var` 행의 셀 하나는 `이름[#속성=값[#속성=값…]]` 형식입니다 [SLU:238-279].

- **`*이름`** → `multi_rows=1` (멀티 로우 필드, §7.4)
- **`!이름`** → `non_empty=1` (빈 칸 금지)
- **필드명 행에 허용되는 속성은 5개뿐입니다** — `sep` · `non_empty` · `multi_rows` ·
  `default` · `format`. 그 외를 적으면 「`##type` 행으로 옮기라」는 예외입니다 [T:81-107].
- **첫 번째 정상 필드는 자동으로 `non_empty=1`** — 빈 셀이 key=0 레코드로 오독되는 것을
  방지하기 위해서입니다 [T:110-120].
- 필드명 셀이 **비어 있거나 `#`으로 시작하면 그 열은 무시**(주석 열)됩니다.
- 같은 이름이 두 열에 나오면 예외입니다(반복 기입 불허).
- `##var` 셀에는 스키마상의 필드 **이름 또는 alias** 어느 쪽을 적어도 됩니다 — 조회가
  「variant명 → 이름 → alias」 순입니다 [SDC:307-328].

### 2.4 한 필드가 여러 열을 차지하는 2가지 방법

1. **셀 병합** — `##var` 행의 병합 셀 하나가 하위 열 범위를 정의합니다.
2. **괄호쌍 열** — 시작 열에 `[이름`, 범위 끝 다음 유효 열에 `이름]`. `[*이름`으로 멀티
   로우도 가능합니다. 짝이 없으면 예외입니다. (병합이 없는 CSV용.) [SLU:346-380]

## 3. 다단 헤더와 열 한정(column-limited) 모드

복합 필드(bean · 컨테이너)의 하위 필드에 이름을 붙이려면 상위 `##var` 행 **아래에 또
`##var` 행**을 둡니다. 파서는 상위 타이틀의 열 범위 안에서 다음 하위 필드 행을 재귀적으로
찾습니다. 깊이 제한이 없습니다.

|A|B|C|D|E|
|--|--|--|--|--|
|`##var`|id|reward *(병합 C~E)*| | |
|`##var`| |item_id|num|cost|
|`##type`|int|Reward| | |
| |1|2001|10|5|

- 하위 열에 이름이 있으면 **열 한정 모드** — 각 필드가 자기 열에서만 읽히고, **원자 타입의
  빈 셀은 기본값**(int→0, `int?`→null, string→"")이 됩니다.
- 하위 열 이름이 없으면 **스트림 모드** — 그 필드의 열 범위(또는 한 셀)를 왼쪽부터 차례로
  소비합니다. **스트림에서는 빈 셀이 건너뛰어지므로 기본값 의미가 없습니다** — 0과 false도
  명시해야 하고, 비우면 필드가 밀립니다.

## 4. 레코드 태그(A열)와 내보내기 필터

- **데이터 행의 A열 = 태그 칸.** 쉼표로 여러 개, 대소문자 무시(소문자 정규화).
- **`##` 태그** — 그 레코드는 항상 무시됩니다. 행 전체 주석의 공식 방법입니다.
  `x` 같은 별도 비활성 마커는 없습니다(그렇게 적으면 이름이 x인 태그가 됩니다).
- **`unchecked` 태그** — 레코드는 내보내되 validator(ref 등) 검사를 건너뜁니다.
- **필터 CLI** — `-i|--includeTag`, `-e|--excludeTag`. 태그 없는 레코드는 항상 통과하고,
  includeTag가 지정되면 교집합이 있어야 통과, 아니면 excludeTag와 교집합이 없으면
  통과입니다. [R:35-46]
- **열 무시** — `##var` 셀이 비었거나 `#` 시작이면 주석 열. 데이터가 채워져 있어도
  내보내지지 않습니다(문서가 명시한 흔한 함정).
- 엑셀 외 소스(JSON·Lua·XML·YAML)에서는 태그를 `__tag__` 필드에 적습니다.

## 5. 테이블 선언 — `__tables__` 시트와 모드·인덱스

테이블은 XML `<table …/>` 또는 엑셀 `__tables__.xlsx`로 선언합니다. `__tables__` 시트도
일반 규칙(`##var` 헤더)을 따르는 표이고, 열은 다음과 같습니다.

|열|의미|
|--|--|
|full_name|테이블 전체 이름 (`item.TbItem`)|
|value_type|레코드 bean 타입|
|define_from_file|true면 데이터 파일의 `##var`·`##type`·`##group`·`##desc` 행에서 bean 정의를 역으로 읽습니다 [SLU:569-677]|
|input|데이터 소스(§9)|
|index|키 지정(아래)|
|mode|`map`(기본) · `list` · `one`(=singleton)|
|group / comment / tags / output|테이블 그룹 · 주석 · 메타 · 출력 파일명|

**모드와 인덱스.**

- `map`(기본) — 단일 기본 키. index 생략 시 value_type의 첫 필드가 키입니다.
- `one` — 레코드 1개, 키 없음. 엑셀에는 단독 읽기 모드가 없어 **데이터 행 1개짜리 일반
  시트**로 적습니다.
- `list` — 키 없이 중복 허용. list라도 index를 지정할 수 있습니다.
  - **연합(union) 유일 키** — `index="id1+id2"`. 조합이 유일해야 합니다.
  - **독립 다중 키** — `index="id1,id2"`(`|`도 허용). 각 키가 각자 유일해야 하고, 키마다
    별도의 맵이 생성됩니다.

데이터 표에는 키를 위한 표기가 없습니다 — 키는 전적으로 선언 쪽 정보입니다.

## 6. bean · enum 정의 — `__beans__` / `__enums__` / 인라인

### 6.1 `__beans__.xlsx`

열 — `full_name` · `parent` · `valueType` · `sep` · `alias` · `comment` · `tags` · `group`,
그리고 멀티 로우 필드 **`*fields`**(하위 열: name · alias · type · group · comment · tags ·
variants). 한 bean이 한 레코드이고, 필드들이 `*fields`의 멀티 로우 원소입니다 — **정의
워크북 자신이 §7.4의 멀티 로우 기구로 읽힙니다.**

- 상속은 `parent` 열입니다. 단 **다형(추상) bean 계층 정의는 엑셀 형식이 지원하지 않아
  XML로** 해야 합니다(wiki/define).
- 인라인 정의 — `define_from_file=true`면 데이터 시트의 `##type` 행이 곧 정의입니다.
  타입 셀 문법은 `타입#속성=값#…` (예: `int#ref=item.TbItem`, `(list#sep=|),int`)입니다.

### 6.2 `__enums__.xlsx`

열 — `full_name` · `flags`(bool) · `unique`(기본 true) · `comment` · `tags` ·
**`*items`**(하위 열: name · alias · value · comment · tags).

- `value` 생략 시 자동 증가(첫 항목 0)입니다.
- `flags=true`면 데이터 셀에 `READ|WRITE` 식 비트 OR 표기가 허용됩니다.
- 데이터 셀의 enum 값은 이름 · alias · 정수 어느 것으로도 적습니다.
- **flags enum의 열 한정 모드** — enum 항목별 하위 열을 만들고, 셀이 비어 있지 않고
  `0`/`false`가 아니면 그 항목이 OR됩니다. 하위 열 이름이 enum 항목이나 alias가 아니면
  예외입니다 [SDC:206-249].

|A|B|C~E|
|--|--|--|
|`##var`|id|access *(병합)*|
|`##var`| |READ / WRITE / NEW|
|`##type`|int|AccessFlag|
| |1|1 / 1 / *(빈칸)* → READ\|WRITE|

- 빈 셀 기본값 — flags이거나 0값 항목이 있으면 0, 아니면 예외입니다.
- **상수 별칭** — 숫자 타입 셀에는 스키마에 등록된 const alias 문자열을 적을 수 있고,
  int는 `0x` 16진수도 허용합니다 [LDU:296-340].

## 7. 컬렉션과 멀티 로우 — 4가지 읽기 방식

### 7.1 한 셀 + 구분자 (`sep`)

- `sep` 지정 위치 3곳 — ① 필드명 `pos#sep=,` ② bean 선언 `<bean sep=",">` ③ 타입 표기
  `(list#sep=|),int`.
- sep 문자열의 **각 문자 하나하나가 모두 구분자**입니다(`sep=,;`면 쉼표도 세미콜론도 구분).
  `#`·`&`는 `\#`·`\&`로 이스케이프합니다.
- 컨테이너 sep은 원소 사이, 원소 타입 sep은 원소 내부 필드 사이입니다. **기본(자동)
  구분자는 현재 없습니다** — sep 없이 한 셀에 `1,2,3`을 넣으면 통째로 int 하나로 파싱을
  시도해 실패합니다.

### 7.2 여러 셀 스트림

필드가 병합·괄호쌍으로 N열을 차지하되 하위 이름이 없으면 그 범위의 셀들이 스트림입니다.
빈 셀은 건너뜁니다. **`}` 셀(또는 토큰)은 컨테이너 종료 표식**입니다 [ES:279]. 스트림 안
bean은 필드 순서대로 소비하고, 다형이면 첫 토큰이 타입 이름입니다(§8.4).

### 7.3 열 한정

- **bean** — 하위 열 이름 = 필드명(또는 alias). 누락되면 「缺失 列」 예외입니다.
- **list · array · set** — 하위 원소들에 이름 붙은 열을 주면(관례상 `0`,`1`,`2`…) 열 순서로
  정렬해 **빈 원소는 건너뛰고** 채워진 것만 모읍니다. 중간을 비우면 원소가 앞으로 당겨지는
  함정이 문서에 명시되어 있습니다.
- **map 열 한정** — **하위 열의 「이름」이 key, 셀 값이 value**입니다 [SDC:512-534].
  빈 셀 항목은 생략됩니다.

|A|B|C~E|
|--|--|--|
|`##var`|id|attrs *(병합)*|
|`##var`| |atk / def / hp|
|`##type`|int|map,string,int|
| |1|10 / 5 / 100 → `{atk:10, def:5, hp:100}`|

### 7.4 멀티 로우 (`*필드명`) — 정밀 규칙

**선언** — 필드명 앞 `*` (= `multi_rows=1`).

**레코드 경계 판정** — 「키 열이 비면 연속」이라는 통설은 근사이고, 정확한 규칙은
[RCS:89-139]입니다.

1. 타이틀 트리에 멀티 로우 필드가 하나라도 있으면 레코드 분할 모드입니다.
2. 완전 빈 행은 **무시**합니다(경계가 아닙니다 — 테이블이 끝나지 않습니다).
3. 어떤 행이 직전 레코드의 **연장(extend)이 되는 조건** — 멀티 로우가 아닌 **모든** 필드의
   열 범위가 전부 빈 칸일 것(하위 타이틀 재귀 판정). 하나라도 채워져 있으면 새 레코드의
   시작입니다.
4. A열(태그 칸)은 판정에 포함되지 않습니다.
5. 첫 필드가 자동 non_empty이므로(§2.3), 새 레코드 행은 사실상 key가 채워진 행입니다 —
   「key가 비면 연속」이 실무 규칙으로 통하는 이유입니다.

**원소 구성** [RCS:141-196]

- 멀티 로우 필드의 원소가 자기도 멀티 로우 하위를 가지면 그 열 범위 안에서 재귀적으로
  다시 분할합니다 — **임의 깊이 중첩**이 됩니다.
- 아니면 레코드에 속한 각 행에서, 그 필드 범위가 빈 행만 건너뛰고 행마다 원소 하나를
  열 한정·스트림 규칙으로 읽습니다.
- 멀티 로우가 **아닌** 필드는 레코드의 **첫 행에서만** 읽습니다.
- 멀티 로우를 지원하는 타입은 컨테이너(list · array · set · map)뿐입니다. 단일 bean ·
  enum에 여러 행을 주면 예외입니다.

|A|B|C~E|
|--|--|--|
|`##var`|id|`*rewards` *(병합)*|
|`##var`| |item_id / num / desc|
|`##type`|int|list,Reward|
| |1|1001 / 1 / 첫째|
| |*(빈칸)*|1002 / 2 / 둘째|
| |2|2001 / 1 /|

→ id=1의 rewards 2개, id=2의 rewards 1개.

## 8. `$type` · `$key` · `$value` — 예약 하위 열 이름

예약 이름의 전체 목록은 [FN]이 확정합니다.

```csharp
FallbackTypeNameKey = "__type__";   // $type의 하위 호환 대체 표기
BeanNullType        = "null";
BeanNotNullType     = "{}";
ExcelTypeNameKey    = "$type";
ExcelValueNameKey   = "$value";
ExcelMapKey         = "$key";
TagKey              = "__tag__";    // 비엑셀 소스의 레코드 태그
```

**`$` 접두 예약 하위 열은 엑셀에서 `$type` · `$value` · `$key` 3개가 전부입니다.**
(`$id` · `*self` 같은 것은 없습니다. `__type__`은 `$type`의 옛 표기 폴백입니다.)

### 8.1 `$type` — 다형·nullable bean의 판별 열

**위치** — 다형(추상) bean 타입 필드의 하위 열 하나로, 다단 헤더에서 이름을 `$type`으로
붙입니다.

**셀에 적을 수 있는 값** [SDC:385-401]

- 구체 서브클래스의 **단순명**(`Circle`), **전체명**(`test.Circle`), 또는 **alias**.
- `null` 또는 빈 칸 → 필드가 nullable일 때만 null. 아니면 예외.
- 알 수 없는 이름 → 예외. **추상 클래스 이름도 예외**입니다.

**변형 선택 방식** — 레코드(원소)마다 `$type` 셀을 읽고, 그 서브클래스의 전체 필드
목록(상속 포함)을 나머지 하위 열에서 이름으로 찾아 채웁니다. **해당 변형에 없는 열은 빈
칸으로 둡니다** — 열 집합은 모든 변형의 합집합이면 됩니다.

|A|B|C|D|E|F|
|--|--|--|--|--|--|
|`##var`|id|shape *(병합 C~F)*| | | |
|`##var`| |$type|radius|width|height|
|`##type`|int|Shape| | | |
| |1|Circle|1.5| | |
| |2|Rect| |2|3|
| |3|矩形 *(Rect의 alias)*| |4|5|
| |4|null *(Shape?일 때만 유효)*| | | |

**nullable이지만 다형이 아닌 bean**(`Reward?`)을 열 한정으로 적을 때도 `$type` 열이
**필수**이며, 허용 값은 `null`(또는 빈 칸) / `{}` / bean 이름 3가지뿐입니다 [SDC:422-439].
`{}`가 「값 있음」 표식입니다.

**멀티 로우·리스트와의 상호작용** — 다형 bean 리스트를 멀티 로우로 두면 **원소가 되는
행마다** 그 행의 `$type` 셀로 변형을 고릅니다. 가로 나열 리스트에서도 원소 블록마다 자기
`$type` 하위 열을 둡니다.

**한 셀(스트림·sep) 다형** — 셀 안에서는 `$type`라는 이름 없이 **첫 토큰이 타입
이름**입니다: `Circle,1.5`. lite 포맷 `{Circle,1.5}`, json 포맷
`{"$type":"Circle","radius":1.5}`, lua 포맷은 `_type_` 키입니다.

### 8.2 `$key` — 멀티 로우 + 열 한정 map의 키 열

`map,K,V` 필드를 멀티 로우로 두고 V의 하위 필드에 열 이름을 붙일 때, **key가 들어갈 하위
열의 이름을 `$key`로** 합니다. 없으면 예외입니다 [SDC:535-550].

|A|B|C|D|E|
|--|--|--|--|--|
|`##var`|id|`*shops` *(병합 C~E)*| | |
|`##var`| |$key|price|stock|
|`##type`|int|map,int,ShopItem| | |
| |1|101|50|3|
| | |102|80|1|
| |2|201|10|99|

→ id=1의 shops = {101:{50,3}, 102:{80,1}}. 각 행이 엔트리 하나입니다.

`$key`가 필요 없는 map 표기 — ① 한 셀 sep 스트림(`k1,v1,k2,v2` 교대) ② 가로 셀
나열(마찬가지로 교대) ③ 열 한정 비멀티로우(**하위 열 이름 자체가 key**, §7.3) ④ 하위 열
이름 없는 멀티 로우(행마다 스트림 엔트리). 중복 key는 어느 모드든 예외입니다.

### 8.3 `$value` — 다형 필드의 값 영역 압축

추상 bean 필드의 하위 열로 `$type`과 `$value`를 두면, 변형별 필드 열을 나열하는 대신
**`$value` 열(들)에 해당 변형의 필드를 스트림(또는 지정 format)으로** 채웁니다
[SDC:390-419].

|A|B|C|D|
|--|--|--|--|
|`##var`|id|shape *(병합 C~D)*| |
|`##var`| |$type|$value#sep=,|
|`##type`|int|Shape| |
| |1|Circle|1.5|
| |2|Rect|2,3|

`$value`에는 자체 `sep` · `format` 속성이 적용되고, 여러 열로 병합해 스트림으로 채울 수도
있습니다. `$value`가 멀티 로우인 경우는 예외입니다.

## 9. 데이터 소스 지정

|input 표기|의미|
|--|--|
|`foo.xlsx`|파일의 모든 유효 시트(A1이 `##`인 시트)를 이어 붙임|
|`sheet@foo.xlsx`|그 시트만|
|`a.xlsx,bag/b.xlsx,c.csv`|여러 파일을 한 테이블로 병합|
|`somedir`|디렉터리 재귀. 경로 조각이 `.` `_` `~`로 시작하면 무시, `.meta`도 무시(엑셀 임시 파일 `~$…` 자동 배제)|
|`foo.json` 등|파일 하나 = 레코드 하나|
|`*@foo.json`|파일 하나 = 레코드 배열|
|`field@foo.json`|특정 필드(점 경로 지원)에서 추출|
|`item.xlsx,*@extra.json`|이종 소스 혼합(키 충돌은 검증이 검출)|

병합은 순수 이어붙이기이고, 유일성 검증은 index가 담당합니다.

## 10. 셀 내용 규약 (타입별)

전부 소스로 확정한 것입니다.

|타입|규약|
|--|--|
|bool|`true/1/y/yes` · `false/0/n/no` (대소문자 무시). 빈 셀(열 한정)→false. datable 문서의 `是/否` 표기는 현 소스에 **없습니다**(§13)|
|int 계열|십진수. int는 `0x` 16진 허용. **스키마 const alias 문자열 허용.** 빈 셀→0(non_empty면 예외)|
|float/double|숫자 또는 const alias. 빈 셀→0|
|string|셀 값 그대로. **`null` → null**(nullable이 아니면 예외), `""` → 빈 문자열, 빈 셀 → nullable이면 null 아니면 "". `string#escape=1`이면 `\n` 등을 실제 문자로 변환|
|datetime|엑셀 날짜 셀 그대로, 또는 `yyyy-M-d[ HH[:mm[:ss]]]`. 빈 셀 금지|
|enum|이름 · alias · 정수. flags는 `A\|B`|
|`T?` (원자)|빈 셀 또는 `null` → null|
|bean(한 셀)|필드 순서대로. 다형이면 첫 토큰 = 타입 이름. nullable 비다형은 선행 토큰 `null`/`{}`/타입명|
|컨테이너(스트림)|원소 나열. `}` 토큰 = 종료. 컨테이너 자체는 nullable 불가|

**빈 셀 의미의 총정리** — 열 한정 모드에서만 「빈 칸 = 기본값」(원자 타입 한정, `default=`
속성으로 재정의, `!`로 금지)이고, 스트림·sep 모드에서는 「빈 칸 = 없는 칸」(건너뜀)이라
기본값 의미가 없습니다. **같은 빈 칸의 뜻이 읽기 모드에 따라 달라집니다.**

## 11. 필드 속성 요약 (선언 위치별)

**`##var`(필드명) 쪽** — `sep` · `default` · `format`(`stream`(기본)/`lite`/`json`/`lua`) ·
`multi_rows`(=`*`) · `non_empty`(=`!`). `format`은 반드시 필드명 쪽입니다.

**`##type`·스키마 쪽** — 타입 표기 `타입#속성=값`, 컨테이너는 `(list#속성),원소타입#속성`.

- `sep=`, `escape=1`(string)
- validator — `ref=테이블명[,…]`(참조 검증. `ref=xxx?`는 0·빈값 무시. 단일 ref는 생성
  코드에 `_Ref` 필드 자동 생성), `path=unity|ue|normal;패턴`, `range=[1,10]`,
  `(list#size=4)`, `set=1;2;3`, `(list#index=x1)`(bean 리스트 원소의 필드 유일성)
- `group=c,s`(필드 내보내기 그룹), 임의 key=value는 tags로 보존
- nullable은 타입명 뒤 `?`

**변형(variant)** — CLI `--variant 필드=이름`으로 필드별 변형 열(`필드@변형` 형태의 열
이름)을 선택하는 기능이 존재합니다. 문서화가 얇은 고급 기능입니다.

## 12. 기타

- **셀 안 JSON·Lua** — `필드#format=json` → `{"x":1,"y":2}`, `#format=lua` →
  `{x=1,y=2}`(다형 키 `_type_`), `#format=lite` → `{1,2,3}`/`{Circle,1.5}`.
- **사람용 이름** — 표시명 전용 행은 없습니다. `##desc` 계열 행이 생성 코드 주석이 되고,
  셀에는 필드 alias를 이름 대신 적을 수 있습니다.
- **A1 `table=` 메타** — 오류 메시지에만 흔적이 남은 폐기된 옛 문법입니다.
- 하위 필드가 2개 이상인 필드는 주석 행의 유효 셀이 정확히 1개일 때만 그것이 그 필드의
  주석으로 인정됩니다 [SLU:636-660].

## 13. 미확인 · 문서-소스 불일치 목록

1. **bool의 `是/否`** — datable.cn은 허용한다고 적었으나 현 소스에 없습니다. 옛 버전을
   반영한 서술로 보이나 옛 소스는 확인하지 않았습니다.
2. **세로표 문서 예시의 `##` 값 열** — 문서 그림대로면 그 열이 주석 처리됩니다(§1.2).
   실제 xlsx 예제는 바이너리라 직접 열어 검증하지 못했습니다.
3. **`required` validator** — 문서·소스 어디에도 없습니다. 빈 값 강제는 `!`가 담당합니다.
4. **`(list#index=…)`의 정확한 범위**(검증만인지 생성 코드 조회까지인지) — 해당
   validator·생성기 소스는 읽지 않았습니다.
5. **`$type#default=…` 조합** — 코드 경로상 동작해야 하나 문서 용례가 없습니다.
6. **`##group` 행이 define_from_file이 아닌 표에서 검증되는지** — 스킵으로 보이나 경고
   여부는 확인하지 못했습니다.
7. **luban_examples의 실제 xlsx 내부**는 직접 열지 않았습니다 — 본문 그리드는 문서 게재
   예시와 소스 규칙에서 재구성한 것입니다.
8. 위키의 `--export_exclude_tags`는 구 CLI이고 현재는 `-e|--excludeTag`입니다. 옛 플래그가
   별칭으로 남아 있는지는 확인하지 않았습니다.
